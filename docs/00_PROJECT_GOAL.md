# 병원 실무지침 AI 프로젝트 목표

> 상태: **계획 검토 대기**
> 기준일: 2026-09-12
> 현재 단계: 1단계 BM25 계획 수립
> 다음 작업: 사용자 승인 전까지 없음

## 1. 프로젝트 목표

병원 실무지침서에서 근거를 찾고, 확인된 근거만 사용해 답변과 출처를 제공하는 내부 직원용 검색·질의응답 시스템을 만든다.

프로젝트는 다음 두 단계로 나눈다.

1. **BM25 기반 검색 데이터 추출 및 검증**
2. **검증된 검색 구조를 이용한 RAG 챗봇 구현 및 검증**

검색이 올바른 근거를 찾는지 확인하기 전에 LLM 답변 품질을 평가하지 않는다. 검색 결과가 부족한 상태에서 LLM이 자연스러운 문장을 만드는 것을 성공으로 판단하지 않는다.

## 2. 현재 코드 기준선

현재 저장소에는 이미 다음 기능이 있다.

- PDF, DOCX, XLSX 문서 추출
- 의미 단위와 토큰 길이를 고려한 chunk 생성
- 한국어·영문·약어를 처리하는 BM25
- FAISS 또는 Supabase pgvector 기반 의미 검색
- BM25와 벡터 검색 결과의 RRF 결합
- 규칙 기반 재정렬과 근거 충분성 검사
- 검색된 chunk만 LLM에 전달하는 답변 생성
- 문서명·페이지 또는 문단 위치 기반 출처 표시
- 관리자용 질문별 BM25 원시 결과와 CSV 다운로드

따라서 1단계에서는 기존 RAG 코드를 제거하지 않는다. LLM을 호출하지 않는 BM25 전용 평가 경로를 분리해 현재 검색 품질을 먼저 측정한다.

## 5. 데이터와 보안 원칙

- 환자 개인정보가 포함된 질문이나 문서는 평가에 사용하지 않는다.
- BM25 평가 중 LLM 또는 외부 AI API를 호출하지 않는다.
- 검색 결과 파일에는 지침서 chunk 원문이 포함될 수 있으므로 `artifacts/`에만 저장한다.
- `artifacts/`는 Git에서 제외된 상태를 유지한다.
- 운영 Supabase에서는 로그인한 관리자의 권한과 RLS를 통과한 문서만 평가한다.
- 평가 결과를 공개 GitHub, 공개 문서 또는 외부 서비스에 업로드하지 않는다.

## 6. 최종 완료 기준

### 1단계 완료 기준

- 실제 등록 문서 수와 chunk 수를 확인한다.
- 지정된 질문을 BM25만으로 검색한다.
- 질문마다 Top-10 원시 결과를 CSV와 JSON으로 저장한다.
- 관리자가 Top-5를 직접 검토한다.
- 성공·실패 사례와 원인을 `02_BM25_RESULT.md`에 기록한다.
- 사용자가 BM25 결과를 승인한다.

### 2단계 완료 기준

- 승인된 BM25 기준선을 유지하면서 의미 검색과 hybrid retrieval을 설계한다.
- 문서 전체가 아닌 최종 근거 chunk만 LLM에 전달한다.
- 근거가 부족하면 정해진 거절 문구를 반환한다.
- 답변의 문장과 출처가 실제 chunk에 의해 뒷받침되는지 검증한다.
- 검색 정확도, 인용 정확도, groundedness, 응답시간, 후속 질문과 혼합 언어 검색을 평가한다.
