# 프로그램 파일을 쉽게 찾아보는 안내서

이 문서는 개발자가 아닌 사용자가 VS Code의 파일 목록을 보고 **어디를 확인해야 하는지**, **무엇을 건드리지 않아야 하는지** 이해할 수 있도록 만든 안내서입니다.

## 먼저 알아둘 점

실제 폴더와 파일 이름은 프로그램 실행, 자동 검사, 배포 설정과 연결되어 있습니다. 그래서 이름을 전부 한글로 바꾸지 않고, 쉬운 한글 설명을 함께 제공합니다.

평소에는 `src`, `tests`, `tools`의 개별 Python 파일을 직접 열 필요가 없습니다. 현재 상태는 `docs_view/index.html`에서 확인하는 것이 가장 쉽습니다.

## 폴더를 한눈에 보기

| 실제 폴더 | 쉬운 이름 | 무엇이 들어 있나 | 일반 사용자가 직접 수정할까? |
|---|---|---|---|
| `src` | 실제 웹앱이 작동하는 핵심 프로그램 | 검색, 근거 선택, 답변, 안전 검사, 화면 | 아니요 |
| `tests` | 기능이 고장 나지 않았는지 자동 확인하는 검사 | 검색·답변·보안·화면 검사 | 아니요 |
| `tools` | 평가·검수·문서 생성에 사용하는 보조 도구 | 성능 평가, 사람 검수 화면, 문서 생성 | 설명 확인 후에만 실행 |
| `docs` | 공식 설명서 | 현재 상태, 요구사항, 설계, 작업일지 | 내용을 확인하는 곳 |
| `docs_view` | 쉬운 문서 화면 | `docs`를 HTML로 변환한 읽기 전용 화면 | 가장 먼저 확인 |
| `workspace/검색_성능평가`, `workspace/RAGAS` | 현재 평가 결과 | 점수표, 비교 결과, 안전한 요약 | Git 추가 전 보안검사 필요 |
| `workspace/데이터_검수`, `workspace/임시작업`, `workspace/과거작업` | 로컬 전용 작업 자료 | 사람 검수, 임시 진단, 과거 원본 | Git에 올리지 않음 |

## src: 실제 앱 프로그램

`src`는 병원 실무지침 AI가 실제로 동작하는 핵심입니다.

| 파일·영역 | 쉬운 설명 |
|---|---|
| `app.py` | 웹앱 시작점 |
| `ui.py`, `answer_ui.py`, `admin_ui.py` | 화면 구성 |
| `query.py` | 질문을 검색에 알맞게 정리 |
| `retrieval.py`, `library.py` | BM25와 의미 검색으로 관련 내용을 탐색 |
| `context.py`, `evidence.py`, `evidence_routing.py` | 답변에 사용할 근거를 선택 |
| `ai.py`, `controlled_generation.py` | AI 답변 후보를 구성 |
| `grounding.py` | 출처·숫자·단위·시간·조건 등을 안전 검사 |
| `presentation.py` | 검증된 답변을 읽기 좋게 표시 |
| `documents.py`, `pdf_layout.py`, `structure.py` | 문서를 읽고 구조화 |
| `repository.py`, `cloud_repository.py`, `storage.py` | 문서와 데이터 저장 처리 |
| `settings.py`, `.env.example` | 실행 설정 안내 |
| `schema.sql`, `storage_schema.sql`, `migrations/` | 데이터베이스 구조 |

**주의:** 이 폴더에서 파일을 삭제하거나 이름을 바꾸면 웹앱이 실행되지 않을 수 있습니다.

## tests: 자동 검사

`tests`는 프로그램을 변경했을 때 기존 기능이 그대로 유지되는지 확인합니다.

- `test_`로 시작하는 파일 하나가 한 종류의 검사 묶음입니다.
- `fixtures`는 검사에 사용하는 승인된 예시 자료입니다.
- 파일이 많다는 것은 같은 기능이 중복되었다는 뜻이 아니라, 여러 안전 조건을 각각 확인한다는 뜻입니다.
- 테스트 실패가 발생하면 실패한 파일 이름을 보고 검색·답변·보안·화면 중 어느 영역인지 구분합니다.

## tools: 평가와 검수 도구

`tools`는 일반 사용자가 상시 실행하는 앱이 아니라, 특정 작업을 수행할 때 사용하는 도구 모음입니다.

| 이름 | 의미 |
|---|---|
| `evaluate` | 품질 또는 성능 평가 |
| `review` | 사람이 확인할 검수 자료 준비 |
| `review_app` | 로컬 검수 화면 |
| `build` | 문서나 검수 입력 생성 |
| `diagnostic` | 실패 원인 진단 |
| `cleanup` | 보안상 남기면 안 되는 임시 자료 점검·정리 |
| `live` | 실제 외부 API를 호출할 가능성이 있음 |

### 현재 열어 본 `workspace_security_cleanup.py`는 무엇인가

이 파일은 **민감한 병원 원문이나 임시 응답이 작업 공간에 남아 있는지 확인하고 정리하는 보안 도구**입니다. 실행 전에 대상 경로와 삭제 범위를 확인해야 하며, 일반적인 앱 실행에는 필요하지 않습니다.

## 파일 상태 표시 읽는 법

VS Code 파일 이름 옆 표시는 다음 의미입니다.

| 표시 | 의미 |
|---|---|
| `M` | Git에 기록된 이전 버전과 비교해 수정됨 |
| `U` | 새 파일이지만 아직 Git에 기록되지 않음 |
| `D` | 파일이 삭제됨 |
| 숫자 | VS Code가 그 파일에서 발견한 문제 개수 |

`M`이나 숫자가 표시되었다고 해서 곧바로 삭제해도 된다는 뜻은 아닙니다.

## 무엇부터 보면 되나

1. 현재 진행 상황은 `docs_view/index.html`을 엽니다.
2. 날짜별 작업은 `07_쉬운_작업일지`를 봅니다.
3. 파일의 역할이 궁금하면 이 문서에서 `src`, `tests`, `tools`를 검색합니다.
4. 프로그램 파일 삭제·이름 변경은 먼저 역할과 참조 관계를 확인한 뒤 승인합니다.

## 안전 원칙

- API 키가 들어 있는 `.env` 파일 내용은 화면이나 문서에 복사하지 않습니다.
- `live` 평가 도구는 외부 API 호출 승인을 받은 경우에만 실행합니다.
- `schema.sql`과 `migrations`는 데이터베이스를 바꿀 수 있으므로 임의 실행하지 않습니다.
- `workspace`와 임시 폴더는 병원 원문이 포함될 수 있으므로 외부에 공유하지 않습니다.
- 현재 평가 결과는 주로 `workspace` 아래에 있습니다. 예전 `artifacts` 폴더는 현재 사용하지 않습니다.
- `workspace` 전체를 한꺼번에 Git에 추가하지 말고, 원문이 없는 요약 결과만 보안검사 후 선택합니다.
- 이해하기 어려운 파일은 이름만 보고 삭제하지 않고 실제 사용 여부를 먼저 확인합니다.
