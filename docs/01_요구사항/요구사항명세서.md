## 1. 프로젝트 기본정보

| 항목 | 내용 |
|---|---|
| 프로젝트명 | SCH Guide AI (화면명: 병원 실무지침 AI) |
| 목적 | 직원이 등록된 병원 지침에서 필요한 내용을 찾고, 원문 근거와 함께 답변을 확인하도록 지원 |
| 주요 사용자 | 직원: 질문·출처 확인. 관리자: 문서·검색 상태·로컬 직원 계정 관리 |
| 현재 단계 | MVP 기능 코드와 회귀 테스트 코드 존재. 이 환경의 운영 검증·두 Retrieval 버전 비교는 미완료 |
| 비교 대상 | 같은 프로젝트의 Version A(BM25 기반), Version B(ChromaDB 기반). 요구사항은 공유 |
| 작성 근거 | 기존 README, 다른 브랜치의 프로젝트 목표 기록, 현재 소스. 신규 요구사항 승인 완료를 의미하지 않음 |

## 2. 기능 요구사항

상태는 현재 작업 트리 기준이다. ‘구현’은 실제 실행 성공이나 두 버전 모두의 구현을 보장하지 않는다.

| ID | 기능명 | 설명 | 사용 목적 | 현재 구현 상태 | 관련 화면 | 관련 코드·모듈 | 비고 |
|---|---|---|---|---|---|---|---|
| REQ-001 | 로그인·권한 | 직원/관리자를 구분하고 유효한 계정만 허용 | 자료 접근 통제 | 구현 | SCR-001 | `mvp/auth.py`, `cloud.py`, `app.py` | 로컬 인증 또는 Supabase 인증 |
| REQ-002 | 질문 입력 | 1~500자 질문, 추천 질문, 새 대화 | 원하는 지침 확인 | 구현 | SCR-002 | `app.py`, `query.py`, `library.py`, `ui.py` | 현재 작업 트리는 문서가 없어도 입력 가능, 전송 시 등록 안내 |
| REQ-003 | 관련 문서 검색 | 접근 가능한 등록 지침에서 근거 후보 검색 | 관련 원문 찾기 | 구현 | SCR-002/003 | `retrieval.py`, `cloud.py`, `repository.py` | 검색 엔진은 구현 차이이며 별도 요구사항 아님 |
| REQ-004 | 근거 기반 답변 | 검색된 근거만 사용해 답변, 부족하면 거절 | 확인되지 않은 내용 추가 방지 | 구현, 연결 설정 필요 | SCR-003 | `ai.py`, `evidence.py`, `grounding.py` | 실제 모델 응답 품질 미검증 |
| REQ-005 | 근거·출처 확인 | 문장별 인용, 문서·페이지/위치·개정일·앞뒤 문맥 | 사용자가 원문 대조 | 구현 | SCR-003/004 | `answer_ui.py`, `ui.py`, `context.py` | 직원 원본 파일 다운로드 기능 아님 |
| REQ-006 | 관리자 접근 | 관리자에게 문서 관리·진단·설정 기능 제공 | 관리 기능 오사용 방지 | 구현 | SCR-005~008 | `admin_ui.py`, `diagnostic_ui.py` | 서버 측 권한 검사 포함 |
| REQ-007 | 문서 수명주기 | PDF/DOCX/XLSX 등록·교체·재색인·삭제 | 지침 최신성 유지 | 구현 | SCR-005 | `documents.py`, `repository.py`, `cloud_repository.py`, `storage.py` | 로컬/운영의 부분 실패 처리 차이는 시스템설계서 참조 |
| REQ-008 | 성능 평가·진단 | 검색 단계·근거 차단 원인·검색 회수율·소요 시간 확인 | 실패 원인 파악 | 일부 구현 | SCR-006, CLI | `diagnostics.py`, `evaluate.py`, `evaluate_cases.py` | RAGAS·두 버전 비교 대시보드 미구현 |
| REQ-009 | 후속 질문 | 이전 질문과 인용 문서 맥락을 활용 | 반복 설명 줄이기 | 구현 | SCR-002 | `app.py`, `query.py` | 이전 AI 답변을 새 근거로 사용하지 않음 |
| REQ-010 | 사용량·재시도 | 전체/사용자별 호출 한도, 재시도 시점, 같은 대화 답변 재사용 | 호출 제어 | 구현 | SCR-002/003/007 | `ai.py::Quota`, `app.py` | 자동 재시도 없음. 사용량 DB는 앱 서버 로컬 |
| REQ-011 | 검토 요청 | 답변 관련 문서·chunk 식별자로 검토 요청 저장 | 지침 품질 점검 | 저장 구현, 처리 관리 화면 미구현 | SCR-003 | `answer_ui.py`, `repository.py`, `cloud.py` | 질문 원문을 검토 요청에 저장하지 않음 |
| REQ-012 | 승인 체크리스트 | 저장된 승인 항목을 관련 답변에서 표시 | 업무 확인 보조 | 조회·표시·저장 함수 구현, 작성 UI 미구현 | SCR-004 | `checklist_ui.py`, `library.py`, 저장소 | 체크 여부 영구 저장 없음 |
| REQ-013 | 직원 계정 관리 | 로컬 직원 생성·비활성화 | 접근 권한 운영 | 로컬 UI 구현 | SCR-007 | `admin_ui.py::account_editor`, `auth.py` | 운영 계정은 Supabase에서 별도 관리 |
| REQ-014 | 백업 | 로컬 지침·계정·색인 백업과 파일 무결성 검사 | 복구용 자료 보관 | 로컬 백업 구현, 복원 UI 미구현 | SCR-008 | `operations.py`, `admin_ui.py` | Supabase 별도 백업 절차 확인 필요 |

## 3. 공통 품질·보안 요구

| ID | 요구 | 현재 근거와 한계 |
|---|---|---|
| NFR-001 | 개인정보·비밀정보 보호 | `protect_private()`의 패턴 검사, 안전한 오류 문구, Git 제외 규칙. 모든 개인정보 탐지를 보장하지 않음 |
| NFR-002 | 출처 위치 보존 | PDF는 실제 파일 페이지, Office는 문단·표·셀 위치. 빈 PDF 페이지도 위치 유지 |
| NFR-003 | 실패를 답변으로 오인하지 않게 표시 | 근거 부족과 API·권한·한도 오류를 구별. 검색된 참고 원문은 답변과 구분 |
| NFR-004 | 처리 중 권한·문서 변경 확인 | 인증 재확인, corpus revision 검사, 세션·검색 캐시 무효화 로직 |
| NFR-005 | 재현 가능한 비교 | 동일 데이터·질문·LLM·Prompt·출력·지표를 적용. 비교 절차는 계획이며 아직 실행하지 않음 |
| NFR-006 | 응답 시간 관찰 | 대화 처리 시간과 CLI 중앙값/p95 구현. 목표 응답 시간·동시 사용자 SLA는 확인 필요 |

## 4. 현재 범위 밖 또는 확인 필요

- ChromaDB 버전의 구현 상태와 공통 계약 준수 여부: 확인 필요.
- RAGAS: 도입 예정. 의료적 적합성 최종 판정은 이 문서의 코드 분석 범위가 아니다.
- 엔진 선택 화면, 두 버전 동시 비교 화면, 검토 요청 처리 화면: 현재 브랜치 미구현.
- 정식 배포 승인, 운영 계정·문서 수, 성능 합격 기준: 담당자 확인 필요.
