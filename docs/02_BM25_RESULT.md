## 1. 결과 요약

승인된 `01_BM25_PLAN.md`에 따라 기존 BM25 수식과 tokenizer를 변경하지 않고 BM25 전용 일괄 평가 기능을 구현했다.

관리자는 다음 작업을 할 수 있다.

1. 검색 가능한 등록 지침서를 선택한다.
2. 기본 5개 질문 또는 한 줄당 하나의 사용자 질문을 입력한다.
3. 벡터 검색과 LLM 호출 없이 저장된 chunk에서 BM25만 실행한다.
4. 질문별 원시 Top-10과 화면의 Top-5를 확인한다.
5. CSV와 JSON을 내려받는다.
6. 같은 결과를 서버의 `artifacts/`에도 저장한다.

일반 직원에게는 이 화면과 실행 경로가 표시되지 않는다. 평가 함수도 관리자 권한을 다시 검사한다.

## 2. 실제 데이터 평가 현황

| 항목 | 결과 |
|---|---|
| 실제 등록 문서 수 | 확인하지 못함 |
| 실제 등록 chunk 수 | 확인하지 못함 |
| 예정 테스트 질문 수 | 5개 |
| 실제 병원 corpus에서 실행한 질문 수 | 0개 |
| 실제 Top-1 정확도 | 측정 불가 |
| 실제 Top-5 검색 성공률 | 측정 불가 |
| 실제 검색 결과 적합성 | 관리자 검토 필요 |

현재 작업 환경에는 GitHub에서 제외된 병원 지침 원본, 로컬 `data/`와 운영 Supabase 로그인 정보가 없다. 기존 프로젝트가 있던 E: 드라이브도 연결되지 않았다.

따라서 실제 문서 수, 실제 chunk 수와 병원 지침 Top-5를 추측하거나 합성 테스트 결과로 대체하지 않았다. `artifacts/bm25_results.csv`와 `artifacts/bm25_results.json`은 실제 등록 문서로 관리자 평가를 실행할 때 생성된다.

이 표는 관리자 평가를 실행하고 원문을 직접 검토한 뒤에만 실제 문서명·페이지·section·score로 갱신한다.

## 4. 구현된 출력

### CSV

경로: `artifacts/bm25_results.csv`

다음 8개 컬럼을 고정 순서로 저장한다.

1. `query`
2. `rank`
3. `bm25_score`
4. `document_name`
5. `page_number`
6. `section_title`
7. `chunk_id`
8. `chunk_text`

- 한 질문당 최대 10행
- UTF-8 BOM 형식
- `chunk_text`는 300자 미리보기가 아니라 전체 저장 chunk
- 0점 chunk도 원시 순위 확인을 위해 저장
- 0점은 검색 성공으로 판정하지 않음

### JSON

경로: `artifacts/bm25_results.json`

CSV 내용 외에 다음 재현 정보를 저장한다.

- corpus revision과 fingerprint
- 평가 시각
- 총 문서 수와 총 chunk 수
- 문서별 chunk 수
- original, actual, expanded query
- tokenizer 설명
- BM25 파라미터
- 질문별 검색 시간
- 양수 점수 결과 수

## 6. 실패 사례

### 실제 검색 실패 사례

실제 corpus를 실행하지 않았으므로 확인된 실제 실패 사례는 없다. 실패 사례가 없다는 뜻이 아니라 아직 측정하지 못했다는 뜻이다.

### 합성 검증에서 확인한 동작

- 한글 2글자 bigram은 문장이 겉보기에는 달라도 일부 글자 조각이 겹치면 낮은 양수 점수를 만들 수 있다.
- 완전히 미등록된 영문 token은 모든 결과가 0점이 될 수 있다.
- 0점 Top-10은 stable sort에 의해 저장 chunk 순서로 표시되므로 관련 검색 결과로 해석하면 안 된다.
- 중복 질문은 한 번만 평가한다.

## 7. 문제 원인과 해석

| 항목 | 원인 | 영향 |
|---|---|---|
| 실제 문서 수·chunk 수 미확인 | 원본·로컬 data·Supabase 세션이 작업 환경에 없음 | 실제 정확도 측정 불가 |
| 실제 Top-5 미판정 | 병원 지침 원문을 읽을 권한 있는 평가 실행이 없음 | 1단계 품질 승인 불가 |
| 한글 부분 겹침의 양수 점수 | 현재 tokenizer의 character bigram 보완 | 낮은 점수의 관련 없는 후보 가능 |
| 0점 Top-10 표시 | 원시 순위를 보존하는 평가 규칙 | 관리자가 점수를 함께 확인해야 함 |
| Word·Excel page 공란 가능 | 해당 형식에 고정 페이지가 없음 | section과 문단·셀 위치 보완 필요 |

## 8. 개선 필요사항

실제 결과를 보기 전에는 BM25 수식이나 tokenizer를 수정하지 않는다. 우선 다음 작업이 필요하다.

1. 병원 지침 데이터가 있는 로컬 프로젝트를 다시 연결하거나 운영 앱의 관리자 평가 화면을 사용한다.
2. 기본 5개 질문을 실행한다.
3. 생성된 CSV와 JSON을 승인된 환경 안에서 확인한다.
4. 질문별 Top-5를 적합·부분 적합·부적합·추출 문제·미등록으로 판정한다.
5. 이 문서의 실제 데이터 표를 갱신한다.
6. 검색 실패가 확인된 경우에만 tokenizer, alias, index field 또는 chunking 수정안을 별도 승인받는다.
