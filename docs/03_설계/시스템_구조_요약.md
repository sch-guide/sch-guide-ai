# SCHAT 전체 구조

## Production 데이터 흐름

```text
Streamlit 질문
  → 사용자가 선택한 문서 범위
  → QueryPlan(domain/topic/aspect/phase/branch/evidence type/context)
  → BM25 + MiniLM 후보
  → RRF + 기존 reranker
  → parent-atomic context
  → evidence gate
  → Facet-slot SourceUnit selection
  → server reconstruction
  → AnswerCoverage / validate_answer()
  → presentation sidecar
  → 답변과 citation UI
```

## Trust boundary

- Provider는 server가 선택한 request-local ID 외의 source identity를 받지 않는다.
- Provider output은 구조·invariant·semantic support가 모두 통과해야만 공개 가능하다.
- Presentation은 검증된 Answer의 text/quote/chunk ID/순서를 바꾸지 않는다.
- Image route는 `pending_image_review`일 때 evidence와 answerability에 연결되지 않는다.
- 최종 UAT artifact에는 질문, SourceUnit 원문, prompt, raw response를 저장하지 않는다.

## Multi-document

- 모든 chunk, parent, evidence, citation은 document ID를 가진다.
- 검색은 사용자가 선택한 document ID로 제한된다.
- 기본 `전체 등록 지침`은 기존 동작이며, admission 보조는 명시적 단일 선택에서만 활성화된다.
- Unknown query는 실제 substantive hit가 선택 문서에만 속하고 기존 evidence gate가 통과해야 hospital로 admit된다.
- 서로 다른 문서의 evidence를 자동 혼합하지 않는다.
- 충돌하는 근거는 각 source citation과 conflict 표시를 요구한다.
