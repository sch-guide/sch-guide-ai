> 비범위: Production 코드·검색·validator·DB/schema·Gold/UAT 변경, 외부 Provider 호출

## 먼저 읽을 한 문장

**현재 SCHAT의 Hybrid Retrieval은 자체 BM25의 단어 기반 검색과 MiniLM의 의미 기반 vector 검색을 병렬로 수행하고, 두 순위를 RRF로 합친 뒤 규칙 기반 reranker와 Evidence 안전 경계를 통과시키는 구조다.**

## 1. 한눈에 보는 전체 시스템 구조

```text
직원 / 관리자 브라우저
          │
          ▼
Streamlit Web App                         src/app.py · src/ui.py
          │
          ▼
질문 입력 / 인증 / 문서 범위
          │
          ▼
QueryPlan                                 src/query.py
정규화 · 검색어 확장 · intent · branch / phase
          │
          ▼
Hybrid Retrieval                          src/retrieval.py · src/cloud.py
          │
          ▼
RRF → 규칙 기반 Reranker                  src/retrieval.py
          │
          ▼
Context Expansion / Parent Atomicity      src/context.py
          │
          ▼
Evidence Gate / SourceUnit Catalog        src/evidence.py
          │
          ▼
승인된 AI Provider의 SourceUnit ID 선택   src/ai.py
          │
          ▼
Server Exact Reconstruction               src/ai.py
          │
          ▼
Validators / AnswerCoverage               src/ai.py · src/evidence.py · src/grounding.py
          │
     ┌────┴─────┐
     ▼          ▼
검증된 답변    Abstention
+ Citation     + 참고 원문
```

핵심 불변식:

1. Vector similarity만으로 답변 가능성을 결정하지 않는다.
2. BM25와 vector 후보는 RRF로 결합한 뒤 기존 규칙 기반 검사를 통과한다.
3. Parent 의미 단위를 부분적으로 잘라 답변하지 않는다.
4. 승인된 AI Provider는 임상 문장을 자유 생성하지 않고 허용된 SourceUnit ID만 선택한다.
5. 서버가 exact text를 재구성하고 validator를 통과한 결과만 표시한다.
6. 근거가 부족하거나 계약이 깨지면 자동 보완하지 않고 abstain한다.

## 2. Hybrid Retrieval 상세 구조

```text
                              사용자 질문
                                   │
                                   ▼
                               QueryPlan
                                   │
                    ┌──────────────┴──────────────┐
                    │                             │
                    ▼                             ▼
          BM25 Lexical Retrieval         MiniLM Semantic Embedding
          단어·구문 기반 검색             의미 기반 384차원 vector
          src/retrieval.py               src/library.py
                    │                             │
                    │                    ┌────────┴────────┐
                    │                    │                 │
                    │                    ▼                 ▼
                    │               Local FAISS      Staff pgvector
                    │               IndexFlatIP      guide_search RPC
                    │                    │                 │
                    └────────────────────┴────────┬────────┘
                                                 ▼
                                                RRF
                                      BM25·vector 순위 결합
                                                 │
                                                 ▼
                                      규칙 기반 Reranker
                                                 │
                                                 ▼
                                       Context Expansion
                                                 │
                                                 ▼
                                          Evidence Gate
                                                 │
                                                 ▼
                                            SourceUnit
```

`Hybrid = BM25 + Semantic Vector Retrieval`이다.

| 구성요소 | 현재 역할 | 실제 구현 |
|---|---|---|
| BM25 | lexical / 단어 기반 후보 검색 | `src/retrieval.py`의 자체 `BM25Index` |
| MiniLM | semantic / 의미 기반 query·chunk vector | `src/library.py`의 FastEmbed `TextEmbedding` |
| FAISS | Local dense similarity | `src/retrieval.py`의 `IndexFlatIP` |
| pgvector | Staff dense similarity | `src/cloud.py`의 `guide_search` RPC |
| RRF | BM25와 vector 결과의 순위 결합 | `src/retrieval.py`의 `rrf()` |
| Reranker | 결합 후보에 compatibility·coverage·threshold 등 적용 | `src/retrieval.py`의 `rerank()` |
| Context expansion | 이웃·절차 순서·branch·parent 보존 | `src/context.py`의 `expand_context()` |
| Evidence gate | 생성 전후 sufficiency와 필수 coverage 판정 | `src/evidence.py`의 `assess_evidence()` |

`rank-bm25==0.2.2`는 설치돼 있지만 Production BM25 runtime은 아니다. Production은 자체 `BM25Index`를 호출한다. 모델 식별자에 `sentence-transformers`가 포함되지만 해당 Python 패키지는 미설치이며, 실제 MiniLM runtime은 `fastembed==0.8.0`이다.

## 3. Local / Staff 실행 모드

```text
                         SCHAT
                           │
                    실행 환경 분기
                ┌──────────┴──────────┐
                │                     │
                ▼                     ▼
           Local Mode             Staff Mode
                │                     │
              SQLite             Supabase Auth/RLS
                │                     │
          공통 BM25 + MiniLM     공통 BM25 + MiniLM
                │                     │
              FAISS               pgvector RPC
                │                     │
                └──────────┬──────────┘
                           ▼
                RRF 이후 공통 안전 경로
```

Local / Staff는 retrieval algorithm의 별도 버전이 아니라 배포·저장 환경의 차이다. Pure BM25 / ChromaDB / Hybrid 비교군과 혼동하지 않는다.

| 항목 | Local (`GUIDE_MODE=local`) | Staff (`GUIDE_MODE=staff`) |
|---|---|---|
| 앱 | Streamlit | Streamlit |
| 인증 | 로컬 계정 DB | Supabase Auth + profile/RLS |
| Catalog | SQLite `catalog.sqlite3` | Supabase tables/RPC |
| BM25 | 서버 메모리 자체 `BM25Index` | 허용 chunk를 앱 cache에 두고 자체 `BM25Index` |
| Embedding | FastEmbed MiniLM | FastEmbed MiniLM |
| Vector engine | FAISS `IndexFlatIP` | Supabase pgvector `guide_search` RPC |
| Fusion 이후 | RRF → 기존 reranker/context/evidence | 동일 |
| 원본 저장 | Local private originals | Supabase private Storage 가능 |

직원 환경에서도 BM25를 Supabase full-text 검색으로 대체하지 않는다. SQLite는 metadata·계정·사용량·vector snapshot 저장소이며 vector similarity 계산 엔진은 아니다.

## 4. Generation / Validation 구조

```text
검증된 Evidence
       │
       ▼
SourceUnit Catalog
       │
       ▼
Request-local ID Schema
       │
       ▼
승인된 AI Provider
허용된 SourceUnit ID만 선택
자유 임상 문장 생성 없음
       │
       ▼
Server Reconstruction
선택 ID → exact source text
       │
       ▼
Validators / AnswerCoverage
Citation · Number · Unit · Time · Condition
Negation · Action · Branch/Phase · Source Order
       │
   ┌───┴────┐
   ▼        ▼
 PASS      FAIL
답변 표시  Abstention / 근거 부족 안내
```

AI Provider 경로는 최종 임상 문장을 마음대로 쓰는 구조가 아니다. 승인된 설정에 따라 Groq 또는 OpenAI 호환 internal/Gemini endpoint를 사용할 수 있다. `src/ai.py`가 요청별 선택 가능 ID를 strict schema로 제한하고, `validate_source_unit_selection()`이 ID·중복·group/facet·순서·branch/phase·coverage를 검사한다. 서버는 `reconstruct_source_unit_answer()`로 원문을 복원한 뒤 `validate_answer()`를 실행한다.

| Gate | 통과 조건 | 실패 동작 |
|---|---|---|
| 질문 | in-scope, clarification 불필요 | 검색/Provider 호출 없이 안내 |
| Pre-LLM Evidence | 필수 group/facet/branch/phase 충족 | `answerable=false` |
| Prompt budget | 필수 근거와 parent atomicity 유지 | `answerable=false` |
| SourceUnit selection | 허용 ID, 순서·coverage 충족 | Provider 결과 폐기 |
| Reconstruction | 선택 ID를 exact text로 변환 | 임의 문장 생성 없음 |
| `validate_answer()` | citation·숫자·단위·행위·support 통과 | 결과 미표시 |
| Citation reassessment | 실제 인용 근거만으로 충분 | `answerable=false` |

Q006 및 운영 out-of-scope 안전 경계는 Provider transport 0회를 유지한다.

## 6. 향후 BM25 / ChromaDB / Hybrid 비교 구조

```text
동일 Gold · 질문 · Chunk Snapshot · Query Processing · Top-k
                         │
             ┌───────────┼───────────┐
             │           │           │
             ▼           ▼           ▼
          Pure BM25   ChromaDB    Current Hybrid
          lexical     vector      BM25 + MiniLM
             │           │        + RRF + reranker
             └───────────┼───────────┘
                         ▼
                동일 Evaluation Harness
                         │
                         ▼
Hit@1/3/5/10 · MRR · Recall · Precision
ID Context Precision/Recall · Latency · Memory
질문 유형별 Failure Analysis
```

한 번에 여러 요소를 바꾸지 않고 검색 방식만 교체해 성능 차이를 비교한다.

공정 비교 조건:

- 사람이 검수한 동일 positive Gold와 동일 질문 집합
- 동일 chunk snapshot, 문서 scope, query normalization/expansion
- 동일 Top-k와 cutoff: 1, 3, 5, 10
- negative/out-of-scope는 positive IR aggregate와 분리
- heading-only chunk를 Gold로 사용하지 않음
- retrieval 결과에서 Gold를 자동 확정하지 않음
- embedding model과 corpus fingerprint 명시

채택은 aggregate뿐 아니라 temporal, product-specific, paraphrase, procedure, fact-specific, branch-specific, table, image, negative/out-of-scope 실패 유형과 안전/UAT 회귀를 함께 본다. 기존 Hybrid 변경은 별도 설계와 승인이 필요하다.

## 9. 상세 기술 설명과 변경하지 않은 범위

### 질문 처리

Streamlit이 질문과 명시적 문서 범위를 수집하면 `plan_query()`가 정규화, 오탈자 보완, intent, domain, 질문 유형, 비교 대상, branch/phase, procedure 요구를 분석한다. Clarification이 필요하거나 domain 밖 질문이면 Provider 호출 전에 차단한다.

### 후보 검색과 재정렬

BM25는 확장 질의를 대상으로 lexical 점수를 계산한다. Vector 경로는 동일 MiniLM 질의 vector를 사용하되 Local은 FAISS, Staff는 pgvector RPC가 dense 후보를 반환한다. RRF는 서로 다른 점수계를 rank 기반으로 결합하며 확률을 산출하지 않는다.

`rerank()`는 heading-only 또는 지나치게 짧은 본문, topic compatibility, lexical support, dense threshold, 핵심어 coverage, focus, 비교 질문의 entity 다양성, 중복과 seed 수를 검사한다.

### Context와 Evidence

`expand_context()`는 같은 문서·section의 연결된 앞뒤 문맥, 페이지 거리, 절차 순서, 명시적 branch와 parent block을 보존한다. 불완전한 parent block은 answer path에서 차단한다. `assess_evidence()`는 LLM 호출 전과 prompt budget 적용 후 필수 document/entity/branch/phase/group/facet coverage를 검사한다.

### 변경하지 않은 범위

- 이 문서 작성 당시의 공식 문서 내용
- `src/` Production 코드와 설정
- Retrieval / validator / database schema
- test fixture, Gold, metric 결과
- `.env` 및 secret
- 외부 Provider/API 호출 상태
- Git branch, commit, tag, push

이 산출물은 실제 실행 코드를 설명하는 검수용 문서다. 존재하지 않는 component를 제안 구조처럼 추가하지 않으며, 평가 코드를 Production 실행선에 포함시키지 않는다.
