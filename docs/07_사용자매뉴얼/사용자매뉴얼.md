# 사용자매뉴얼

기준일: 2026-09-17 · 현재 작업 폴더의 화면 코드 기준

## 1. 접속과 로그인

1. 관리자가 안내한 접속 주소를 브라우저로 연다.
2. 직원 계정으로 로그인한다. 운영 화면은 직원 이메일, 이 PC용 화면은 아이디를 사용한다.
3. 이 PC에서 처음 실행하는 경우에는 관리자 계정 만들기가 표시된다. 관리자만 아이디와 비밀번호(10자 이상), 확인 비밀번호를 입력한다.
4. ‘직원 전용 로그인 설정이 필요합니다’가 나오면 관리자에게 연결 설정을 요청한다.

주소·계정·비밀번호는 이 문서에 기재하지 않는다. 로그인이 되지 않으면 직원 등록·활성 상태를 확인한다. 로컬 로그인 실패가 누적되면 15분 뒤 다시 시도하라는 안내가 나올 수 있다.

### 개발 PC에서 화면을 여는 경우

프로젝트 폴더의 PowerShell에서 실행한다. 이미 서버가 켜져 있으면 기존 주소를 사용한다.

```powershell
$env:GUIDE_MODE='local'
$env:GUIDE_STORAGE_BACKEND='local'
.\.venv\Scripts\python.exe -m streamlit run streamlit_app.py --server.address 127.0.0.1 --server.port 8504
```

브라우저에서 `http://127.0.0.1:8504`를 연다. VS Code에서는 명령 팔레트의 `Simple Browser: Show`에 주소를 넣을 수 있다. 이 명령은 현재 터미널에 로컬 설정을 적용하며 운영 로그인 설정을 대신하지 않는다. 이번 문서 작업에서 서버를 새로 실행하지 않았으므로 현재 접속 가능 여부는 확인 필요다.

## 2. 질문하기

1. ‘AI 채팅’을 연다.
2. 첫 화면 가운데 입력창에 확인할 지침 주제와 항목을 적는다. 최대 500자까지 입력할 수 있다.
3. 추천 질문을 누르면 입력창에 문구가 들어간다. 필요한 내용으로 고친 뒤 Enter로 전송한다. 줄바꿈은 Shift+Enter다.
4. 이전 질문을 이어 묻고 싶으면 대화가 있는 상태에서 ‘이전 질문에 이어서 묻기’를 선택한다. ‘그럼’ 같은 표현은 자동으로 후속 질문으로 판단될 수도 있다.
5. 다른 주제로 시작할 때는 ‘새 대화 시작’을 누른다.

환자 이름·등록번호·전화번호 등의 식별정보를 입력하지 않는다. 추천 질문이 있다는 사실만으로 해당 지침이 등록됐다고 볼 수는 없다.

지침이 아직 없으면 입력은 가능하지만 전송 시 문서 등록 안내가 나온다. 관리자는 ‘지침서 등록하러 가기’를 누르고, 직원은 관리자에게 등록을 요청한다.

## 3. 답변 읽기

- 답변과 각 문장 옆의 출처 번호를 함께 확인한다.
- 근거 문서 수와 개정일을 확인한다. 오래된 지침 경고가 있다면 현재 적용 기준을 담당 부서에 확인한다.
- ‘등록된 지침서에서 확인할 수 없습니다’는 등록 자료의 근거가 부족하거나 검증을 통과하지 못했다는 뜻이다. 질문을 구체화하거나 문서 등록 상태를 확인한다.
- 서로 다른 지침의 내용이 충돌하면 양쪽 원문을 확인한다.
- ‘검색된 참고 원문’은 AI가 확정한 답변과 구별해 읽는다.
- 연결·사용량 오류가 나오면 표시된 안내를 따른다. ‘같은 질문 다시 시도’ 버튼은 안내된 대기 시간 뒤 사용한다.

## 4. 근거와 출처 확인

1. 답변 아래 문서·페이지/위치 버튼을 누른다.
2. 인용 문장과 문서명·항목·개정일을 확인한다.
3. ‘검색된 원문 전체 보기’를 펼치면 해당 검색 문단을 확인할 수 있다.
4. 문맥이 더 필요하면 ‘앞뒤 문단도 보기’를 켠다.

PDF의 페이지 번호는 파일 첫 장을 1로 센 값이므로 인쇄된 쪽수와 다를 수 있다. Word는 문단·표 위치, Excel은 시트·셀 주소가 표시된다. 여기서 원문 전체는 해당 검색 문단이며 원본 파일 전체를 다운로드하는 기능은 아니다.

‘체크리스트 열기’가 보이면 저장된 승인 항목을 확인할 수 있다. 체크 여부는 기록으로 영구 저장되지 않는다. ‘답변 검토 요청’은 문서·출처 식별자를 이용해 요청을 남기며, 요청 처리 현황 화면은 현재 없다.

## 5. 관리자: 문서 등록

1. ‘지침서 관리’ → ‘문서 추가’ 또는 ‘새 지침서 등록 / 기존 지침서 교체’를 연다.
2. 등록 방식을 ‘새 지침서 등록’으로 선택한다.
3. PDF, DOCX, XLSX 중 하나를 선택한다. 파일 제한은 화면상 20MB다. `.doc`, `.xls`는 지원 형식으로 변환한다.
4. 추출 누락과 경고를 확인하고 원본에서 해당 위치를 검토한다. 스캔 PDF는 OCR 설정 또는 사전 처리가 필요하다.
5. 문서 제목·분류·알고 있는 원문 개정일을 입력한다. 개정일을 모르면 비워둔다.
6. 원본과 개인정보 여부를 확인한 뒤 검토 확인란에 체크한다.
7. ‘저장하고 검색 인덱스 생성’을 누르고 검색 준비 완료 안내를 기다린다.
8. 문서 상태가 ‘검색 가능’인지 확인하고 AI 채팅으로 돌아간다.

문서 등록만으로 AI 연결이 완료되지는 않는다. AI 서버 설정이 없으면 관리자에게 별도 연결을 요청한다.

## 6. 관리자: 교체·재색인·삭제

- **교체:** 등록 방식에서 교체할 기존 지침을 선택한 뒤 새 파일로 등록 절차를 진행한다. 실패하면 새 문서와 기존 문서의 상태를 모두 확인한다.
- **재색인:** 목록의 문서를 선택하고 ‘이 문서 검색 인덱스 재생성’을 누른다. 여러 문서는 ‘등록 중인 모든 문서 재색인’을 사용하고 실패 건수를 확인한다.
- **삭제:** ‘선택 문서 삭제’를 누른 뒤 문서명과 확인란을 확인하고 삭제한다. 검색 및 연결된 체크리스트에 영향을 준다.

검색 준비 실패·원본 접근 오류가 있으면 반복 등록 전에 저장된 오류 안내를 확인한다. 운영 문서 교체가 중간에 실패한 경우는 관리자 점검이 필요하며 정상 완료로 보지 않는다.

## 7. 관리자: 진단·계정·백업

- 검색 실패: ‘검색 실패 진단 · 관리자 전용’에서 문서와 질문을 선택하고 ‘실제 검색 파이프라인 진단’을 누른다. AI 재시험을 선택하면 실제 연결된 AI를 호출하고 사용량이 반영될 수 있다.
- 결과 저장: 진단 JSON과 BM25 CSV에는 지침 원문이 포함될 수 있다. 승인된 관리 장소에서만 보관한다.
- 계정: 이 PC용 모드에서는 관리자 설정 영역에서 직원을 등록하거나 비활성화할 수 있다. 운영 계정은 Supabase 관리 담당자가 처리한다.
- 백업: 로컬 원본 저장소를 사용하는 관리자 화면의 ‘지침서·계정·색인 백업’을 누른다. 성공과 무결성 검사 안내를 확인한다. 복원 버튼과 운영 Supabase 백업 기능은 없다.

## 8. 오류가 발생했을 때

| 표시·상황 | 확인할 사항 |
|---|---|
| 입력은 되지만 문서 등록 안내 | 검색 가능한 지침이 등록돼 있는지 확인 |
| AI_SETUP / AI_APPROVAL | 관리자가 AI 연결·이용 조건 설정 확인 |
| AI_RATE / AI_LIMIT | 표시된 대기 시간 또는 사용 한도 확인 |
| CORPUS_CHANGED | 처리 중 문서가 변경됨. 목록을 새로 확인하고 다시 질문 |
| ACCESS / 로그인 만료 | 다시 로그인하고 계정 활성 여부 확인 |
| PDF/Office/OCR/INDEX 오류 | 파일 형식·암호·크기·추출 경고·검색 모델 준비 상태 확인 |
| DATABASE / STORAGE 오류 | 관리자에게 오류 단계·코드 전달. 키나 원문을 함께 보내지 않음 |
| Port … is not available | 같은 포트의 기존 앱 주소 확인 또는 다른 빈 포트로 실행 |
| Python 실행 버튼으로 오류 | `.py` 직접 실행 대신 위 Streamlit 명령 사용 |

사용을 마치면 로그아웃한다. 대화는 현재 세션 중심이며 장기 보관 기록으로 사용하지 않는다.
