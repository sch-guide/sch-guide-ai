# SCHAT 개발 용어를 쉽게 설명

| 용어 | 쉬운 설명 |
|---|---|
| BM25 | 질문과 지침서에서 같은 단어나 중요한 단어를 찾아주는 검색 방식 |
| MiniLM | 문장의 뜻을 숫자 묶음으로 바꾸는 도구 |
| Gemini Embedding 2 | Gemini가 답변을 쓰는 기능과 별개로, 문장의 뜻을 검색용 숫자 벡터로 바꾸는 외부 임베딩 모델 |
| Vector 검색 | 문장을 숫자로 바꾼 뒤 뜻이 가까운 문장을 찾는 방식 |
| ChromaDB | 문장을 숫자 벡터와 함께 저장하고 비슷한 문장을 찾는 저장소 |
| Hybrid 검색 | 단어 검색과 의미 검색을 함께 사용하는 방식 |
| RRF | 서로 다른 검색 결과의 순위를 하나로 합치는 방법 |
| Reranker | 검색된 후보를 한 번 더 살펴보고 관련성이 높은 순서로 재정렬하는 기능 |
| Chunk | 긴 지침서를 검색하기 좋게 나눈 작은 문서 조각 |
| SourceUnit | 답변에서 실제로 사용 가능한 최소 근거 단위 |
| Gold | 사람이 확인해 정답 기준으로 승인한 질문과 근거 |
| Deferred | 아직 확신할 수 없어 승인을 보류한 항목 |
| Validator | 답변의 출처·숫자·조건·행동 등이 근거와 맞는지 검사하는 안전장치 |
| Citation | 답변이 어느 문서와 페이지를 근거로 했는지 보여주는 출처 표시 |
| Fallback | AI 답변이 안전 검사를 통과하지 못했을 때 검증된 원문 답변으로 되돌아가는 기능 |
| Abstention | 근거가 부족하거나 범위 밖 질문일 때 억지로 답하지 않고 중단하는 것 |
| UAT | 실제 사용자가 물을 법한 질문으로 기능을 확인하는 시험 |
| RAGAS | 검색과 답변 품질을 여러 지표로 평가하는 도구 또는 평가 방식 |
| Hit@10 | 검색 결과 10개 안에 정답 근거가 하나라도 들어간 질문의 비율 |
| MRR | 정답 근거가 검색 결과 앞쪽에 나올수록 높아지는 점수 |
| Recall@10 | 필요한 정답 근거 중 상위 10개에서 얼마나 많이 찾았는지 나타내는 비율 |
| Precision@10 | 상위 10개 검색 결과 중 실제 정답 근거가 얼마나 포함됐는지 나타내는 비율 |
| Live 호출 | 실제 외부 AI 서비스에 요청을 보내 답변을 받는 것 |
| Mock 테스트 | 외부 서비스에 실제 요청하지 않고 가짜 응답으로 동작을 확인하는 시험 |
| Fail-closed | 문제가 생기면 추측해 계속하지 않고 안전하게 중단하는 방식 |

## 가장 중요한 구분

### 검색이 잘된다는 것과 답변이 안전하다는 것은 다릅니다

- 검색 평가는 필요한 지침서 부분을 잘 찾았는지 확인합니다.
- 답변 평가는 찾은 근거의 의미를 AI가 바꾸지 않았는지 확인합니다.
- 두 단계가 모두 통과해야 실제 사용 준비가 됐다고 판단할 수 있습니다.

### Production과 Evaluation-only는 다릅니다

- **Production**: 실제 웹 시연이나 서비스 경로에서 사용하는 기능
- **Evaluation-only**: 비교와 실험을 위해 따로 만든 기능으로 실제 서비스에는 연결하지 않음

ChromaDB-only 평가와 Gemini 관련 진단 도구는 비교·검증 목적의 evaluation-only 경로입니다.

### Gemini 임베딩과 Gemini 답변 생성은 다릅니다

- **Gemini Embedding 2**: 질문과 문서를 검색용 숫자 벡터로 바꿉니다.
- **Gemini 답변 생성**: 찾은 근거를 읽고 자연어 답변을 만듭니다.
- 같은 회사의 모델이지만 역할과 평가 기준이 다르므로 작업일지에서도 분리해 기록합니다.
