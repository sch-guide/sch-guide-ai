## 7. 원인 구분

### Chunking / 비본문 후보 처리: 확인된 주요 문제

가장 명확한 원인이다. 제목과 페이지 반복 표제가 독립 chunk로 생성되고 BM25 후보에서 본문과 동일하게 경쟁한다. 답이 있는 질문의 60%에서 제목-only가 1위를 차지했고, SCHAT Top 10의 26%를 차지했다. Q002의 제목-only 3위는 partially_relevant로 판정됐지만 절차 본문이 없어 단독 답변 근거로는 불충분하다.

추가로 코퍼스에는 완전 중복 그룹 3개, 중복 그룹 소속 chunk 8개, 8자 미만 짧은 본문 chunk 7개가 기록돼 있다. 모두 오류라고 단정할 수는 없지만 반복 표제와 짧은 표 헤더가 후보 공간을 점유하는 현상은 재검증 대상이다.

### Tokenizer: 표현 민감성 신호는 있으나 단독 결함으로 확정 불가

Q001 “진정간호 목적은?”은 정답 2위인데, 같은 의도의 Q004 “진정 간호의 목적은 무엇인가요?”는 정답 1위다. 현재 tokenizer는 붙여 쓴 “진정간호”를 보존하면서 한국어 2-gram을 추가하고, 띄어 쓴 Q004에서는 “진정”과 “간호”를 별도 토큰으로 만든다. 이 차이가 점수에 영향을 준 신호는 있다.

그러나 두 엔진이 동일 tokenizer를 사용했고 두 질문에서 첫 관련 순위도 엔진별로 완전히 같으며, Q001의 직접 원인은 매우 짧은 제목 chunk가 1위를 차지한 것이다. 따라서 tokenizer_mismatch를 확정 결함으로 판정하지 않는다. 제목-only 처리 전후에 붙임/띄어쓰기 쌍 질문을 늘려 별도 회귀 평가하는 것이 우선이다.

### Query expansion: 이번 실패의 원인 아님

6개 질문 모두 original_query, normalized_query, expanded_query가 동일하다. alias·동의어 확장이나 철자 보정이 적용되지 않았으므로 잘못된 확장이 후보를 끌어온 사례는 없다. 반대로 확장 미적용의 이득도 검증하지 못했다.

현재 5개 양성 질문이 모두 Top 3 안에서 관련 chunk를 찾았으므로 query expansion은 우선 개선 항목이 아니다. 향후 표현 불일치 질문을 추가해 원문 query와 확장 query를 분리 비교할 때 판단한다.

## 9. BM25 단계 승인 판단

**현재 BM25 단계의 정식 승인은 보류한다. RAG 단계로 넘어가기 전에 최소 개선과 재검증이 필요하다.**

근거는 다음과 같다.

1. Q001~Q005의 Hit@3·5·10은 100%로 후보 회수 성능은 통과 가능 수준이다.
2. Hit@1은 20%이며 5개 중 3개 질문에서 제목-only chunk가 1위다.
3. SCHAT의 양성 질문 Top 10 중 제목-only 비율이 26%로 baseline 10%보다 높다.
4. 전체 72/72 판정이 완료되어 지표 산출의 판정 완전성 문제는 해소됐다.
5. Q003은 질문 시점과 어긋난 진정 후 내용이 1위다.
6. tokenizer와 query expansion을 바꿀 직접 근거는 아직 부족하며, 우선순위는 chunking 및 비본문 후보 처리다.

RAG 전에 필요한 최소 작업은 다음과 같다.

1. 제목-only chunk를 독립 BM25 후보에서 제외하거나 다음 본문과 결합하는 방안을 설계한다.
2. 검색 로직 변경은 별도 계획과 사용자 승인 후 수행한다.
3. 같은 질문·같은 chunk 조건으로 SCHAT와 rank-bm25를 다시 실행한다.
4. Hit@1 개선, Hit@3 유지, 음성 대조 0점 유지, 제목-only 빈도 감소를 확인한 뒤 BM25 승인을 다시 판단한다.
