## 1. 목적과 승인 경계

현재 BM25 평가에서 답이 있는 Q001~Q005의 Hit@3·5·10은 100%였지만 Hit@1은 20%였다. Q001, Q002, Q005에서는 제목-only chunk가 관련 본문보다 먼저 1위를 차지했다. 이 계획은 제목과 출처 정보를 잃지 않으면서 제목-only chunk가 BM25 순위를 점유하지 않도록 하는 방법을 비교하고, 구현 가능한 한 가지 구조를 정한다.

이 문서는 설계 산출물이다. 사용자 승인 전에는 다음 작업을 하지 않는다.

- mvp/retrieval.py, mvp/library.py, mvp/structure.py 등 검색·청킹 코드 수정
- tokenizer 또는 query expansion 변경
- SCHAT BM25Index를 rank-bm25로 교체
- 기존 chunk, 인덱스, 원본 문서 또는 BM25 평가 산출물 수정
- RAG 구현 또는 LLM 호출

## 2. 현재 근거와 문제 정의

### 평가 근거

| 항목 | SCHAT BM25Index | rank-bm25 |
|---|---:|---:|
| 양성 5문항 Hit@1 | 20% | 20% |
| 양성 5문항 Hit@3·5·10 | 100% | 100% |
| 양성 5문항 MRR | 0.600 | 0.600 |
| 양성 Top 10 제목-only 노출 | 13/50, 26% | 5/50, 10% |
| 제목-only 1위 질문 | Q001, Q002, Q005 | Q001, Q002, Q005 |

현재 평가에서 확인된 제목-only ID는 00001, 00002, 00008, 00012, 00018, 00038, 00042다. 대표 형태는 섹션 제목인 “15. 진정간호”, “8. 외래에서의 소아 진정치료 절차”와 여러 페이지에 반복되는 “간호실무지침”이다.

### 질문별 실패

- Q001 “진정간호 목적은?”: 제목-only 00002가 1위이고 목적 본문 00003이 2위다.
- Q002 “진정간호 절차는?”: 제목-only 00002가 1위이고 부분 관련 절차 본문 00013이 2위다. 제목-only 00042도 3위다.
- Q005 “진정간호 주의사항은?”: 제목-only 00002가 1위이고 주의사항 본문 00028이 2위다.
- Q003 “진정 전 준비사항은?”: 1위 00026은 제목-only가 아니라 진정 후·검사 중 모니터링 본문이다. 따라서 제목-only 처리만으로 해결되지 않는 별도 문제다.

## 3. 현재 구조와 제약

현재 흐름은 다음과 같다.

1. mvp/structure.py의 semantic_blocks()가 제목·문단·표를 의미 단위로 나눈다.
2. mvp/library.py의 make_chunks()가 큰 의미 단위를 분할하고 Chunk에 문서명, page/location, title, section, 이전·다음 ID와 parent_id를 저장한다.
3. mvp/retrieval.py의 BM25Index가 chunk.text와 chunk.section을 같은 lexical_tokens()로 색인한다.
4. 로컬 검색과 클라우드 검색은 BM25 Top 40과 dense 후보를 RRF로 결합한다.
5. rerank()는 has_substantive_body()로 일부 짧은 표제를 제거한 뒤 최종 seed를 선택하고, expand_context()가 인접 chunk를 문맥으로 추가한다.

직접 BM25 평가는 4~5단계를 거치지 않고 BM25 점수 그대로 Top 10을 만든다. 따라서 후단 필터가 있더라도 제목-only가 BM25 후보 공간과 평가 순위를 차지한다.

현재 Chunk에는 구조 유형이 별도 필드로 저장되지 않는다. has_substantive_body()는 section/title과 같은 표제는 감지하지만, “간호실무지침”처럼 짧은 반복 페이지 표제가 문서 title이나 section과 문자열로 같지 않으면 본문으로 볼 수 있다. 그러므로 기존 함수만 그대로 사용하면 현재 7개 제목-only 유형을 모두 안정적으로 처리하지 못한다.

## 6. 방식 A: 제목-only chunk를 BM25 독립 후보에서 제외

### 설계

원본 Chunk와 저장된 벡터는 그대로 유지한다. BM25Index를 만들 때 입력 순서와 같은 길이의 title-only mask와 본문별 inherited title context를 함께 계산한다. 제목-only 위치는 postings와 BM25 문서 통계에서 제외하고, 의미 있는 섹션 제목은 같은 문서의 다음 검색 가능 본문을 색인할 때 context로만 사용한다. scores()는 기존과 같은 길이의 numpy 배열을 반환하되 제외 위치의 점수는 항상 0으로 유지한다.

이 방식은 다음 불변식을 지킨다.

- Chunk ID, 원문, index, page/location, section, parent_id와 인접 ID를 바꾸지 않는다.
- BM25 점수 배열 위치는 입력 chunks 위치와 항상 일치한다.
- title-only chunk는 BM25 lexical Top 40에 들어가지 않는다.
- 제목은 삭제하지 않고 저장 코퍼스에 남긴다. 의미 있는 섹션 제목은 다음 본문의 BM25 index context로 상속하되 반환되는 원문과 citation은 본문 chunk를 가리킨다.
- 반복 페이지 머리말은 문서 형식 정보로 보존하지만 다음 본문의 의미 context로 상속하지 않는다.
- rank-bm25 baseline은 변경하지 않는다.
- tokenizer와 QueryPlan.expanded는 변경하지 않는다.

### 제목-only 판정 정책

하드코딩된 병원 문서명 목록을 만들지 않고 다음 두 구조 신호만 사용한다.

1. 명시적 제목: 정규화한 chunk 전체가 document_name, 확장자를 뺀 문서명, title 또는 section 경로의 한 항목과 동일하면 제목-only다.
2. 반복 페이지 표제: PDF에서 각 페이지의 첫 chunk에 해당하고, 짧고 문장 종결형이 아닌 동일 원문이 같은 문서의 둘 이상 페이지에서 반복되면 running header로 판정한다.
3. 제목 context 상속: 명시적 section 제목만 같은 document_id 안의 다음 검색 가능 본문에 전달한다. 이미 본문 section에 같은 제목이 있으면 중복하지 않고, 다른 문서로 넘기거나 running header를 전달하지 않는다. 다음 본문이 없으면 상속 없이 제목 chunk만 보존한다.

짧다는 이유만으로 제외하지 않는다. 짧은 투약 지시나 주의 문장을 보존하기 위해 표 머리글, 캡션, 짧은 본문은 위 두 조건을 충족하지 않으면 이번 제목-only 정책의 제외 대상이 아니다. 판정은 원문을 바꾸지 않는 순수 함수로 만들며 결과는 BM25Index 인스턴스 생명주기 동안만 유지한다.

### 호출자 관점 사용 예시

아래는 미구현 의사코드다. 기존 호출자는 변경하지 않는다.

```python
# 로컬 검색, 클라우드 검색, 평가 도구 모두 기존 호출 형태 유지
index = BM25Index(chunks)
scores = index.scores(plan.expanded)

# scores와 chunks는 계속 위치로 대응한다.
# 제목-only 위치는 0이고 관련 본문은 상속된 제목 context와 함께 색인된다.
lexical = [i for i in stable_descending(scores) if scores[i] > 0][:40]
```

내부 표면은 다음 정도로 제한한다.

```python
# 미구현 의사코드
@dataclass(frozen=True)
class BM25CorpusPolicy:
    searchable: tuple[bool, ...]
    inherited_titles: tuple[str, ...]

def bm25_corpus_policy(chunks: Sequence[Chunk]) -> BM25CorpusPolicy: ...

class BM25Index:
    def __init__(self, chunks: Sequence[Chunk]): ...  # 공개 서명 유지
    def scores(self, query: str) -> np.ndarray: ...   # 길이와 위치 계약 유지
```

BM25Index가 판정 mask, 상속 title context, eligible 문서 수, 평균 길이와 postings의 단일 소유자가 된다. BM25CorpusPolicy는 인덱스 내부의 두 평행 배열을 잘못 맞추지 않기 위한 비공개 불변 값이며 외부 설정으로 노출하지 않는다. 별도 서비스나 런타임 선택 옵션은 만들지 않는다.

### 예상 효과

- Q001: 00002와 반복 표제 후보가 제외되어 목적 본문 00003이 2위에서 1위로 이동할 가능성이 높다.
- Q002: 00002와 00042 및 반복 표제가 제외되어 00013이 2위에서 1위로 이동할 가능성이 높다.
- Q005: 00002가 제외되어 주의사항 본문 00028이 2위에서 1위로 이동할 가능성이 높다.
- Q004: 기존 본문 1위를 유지해야 한다.
- Q003: 00026이 본문이므로 순위가 자동으로 개선되지는 않는다.
- 양성 Hit@1은 현재 20%에서 예상 80%(Q001·Q002·Q004·Q005)까지 개선 가능하다. 이는 구현 전 예상이며 재실행 결과로 확정해야 한다.
- 양성 Hit@3은 관련 본문을 제거하지 않으므로 100% 유지 가능성이 높다.

### 장점

- 현재 실패 원인에 직접 대응하며 결과가 결정적이다.
- chunk 재생성, 임베딩 재계산, DB migration이 필요 없다.
- 기존 72개 label과 chunk ID를 그대로 재사용할 수 있다.
- 본문 citation은 원래 본문의 page/location을 그대로 사용하고, 상속 제목 때문에 제목 chunk의 page로 바뀌지 않는다.
- 로컬 BM25와 클라우드의 로컬 BM25 캐시에 동일 정책이 적용된다.

### 단점과 위험

- 반복 페이지 표제 판정이 과도하면 짧은 실제 지시를 제외할 수 있다.
- 제목 context를 잘못된 다음 본문에 상속하면 다른 항목의 점수를 오염시킬 수 있다. document 경계, 검색 가능 본문 존재 여부와 section 중복 검사를 테스트로 고정해야 한다.
- 제목-only가 dense 후보로 들어오는 것까지 자동으로 금지하는 설계는 아니다. 현재 rerank의 비본문 필터와 함께 동작하지만, running header에 대한 최종 검색 경로 회귀 테스트가 필요하다.
- BM25 유효 문서 수와 평균 길이가 바뀌므로 본문 간 점수도 일부 변한다. Hit@3 유지 여부를 반드시 재검증해야 한다.

## 7. 방식 B: 제목-only chunk를 바로 다음 본문과 병합

### 설계 개요

semantic_blocks() 또는 make_chunks() 단계에서 제목 block을 보류했다가 같은 문서·섹션의 다음 본문 앞에 붙인다. 병합 결과는 제목과 본문을 모두 text에 포함하고 section도 유지한다.

### 예상 효과

제목 토큰과 본문 내용이 한 BM25 문서에 함께 있어 Q001·Q002의 의도어가 강화될 수 있다. 그러나 “15. 진정간호”를 바로 다음 목적 본문에 붙이면 Q005에서도 일반 진정간호 토큰이 목적 본문을 강화한다. 길이 정규화로 완화될 수 있지만 주의사항 본문이 반드시 1위가 된다는 보장은 없다.

### 장점

- 제목과 본문의 의미 연결이 한 검색 단위에 명시된다.
- 제목만 있는 검색 결과가 줄어든다.
- 문서를 읽을 때 제목과 내용이 함께 보여 이해하기 쉽다.

### 단점과 위험

- chunk text, ID, index, parent 및 previous/next 연결이 바뀐다.
- 모든 벡터를 다시 만들고 로컬·Supabase 문서를 재색인해야 한다.
- 기존 72개 수동 label을 새 ID에 그대로 적용할 수 없다.
- 제목이 페이지 끝, 본문이 다음 페이지에 있으면 현재 Chunk의 단일 page 필드로 양쪽 위치를 정확히 표현할 수 없다. 출처 span 모델을 추가하지 않으면 citation이 모호해진다.
- 표 제목을 다음 표 chunk에 병합할 때 110토큰 제한과 반복 header 로직이 다시 작동해 예기치 않은 분할이 생길 수 있다.
- rollback에는 이전 chunk 집합과 임베딩을 복구하거나 원문 전체를 재색인해야 한다.

이 방식은 현재 문제에 비해 변경 반경이 크고, “기존 인덱스와 원본 결과를 유지”해야 하는 이번 단계에 맞지 않아 기각한다.

## 8. 방식 C: 제목-only chunk의 BM25 score 감점

### 설계 개요

방식 A와 같은 title-only mask를 계산하되 postings에서는 유지하고 scores() 마지막에 해당 위치 점수에 고정 계수를 곱한다. chunk·citation·인덱스 위치는 바꾸지 않는다.

### 예상 효과

Q001에서는 제목 8.749와 본문 5.533이므로 약 0.63 미만 계수면 현재 순서를 뒤집을 수 있다. Q005에서는 제목 8.749와 관련 본문 0.999이므로 약 0.114 미만이 필요하다. 즉 0.5 같은 완만한 감점은 Q005를 해결하지 못하며, 0.1 수준의 강한 감점은 사실상 후보 제외에 가까워진다.

### 장점

- 제목-only 검색 자체를 완전히 금지하지 않는다.
- chunk, 벡터, ID, citation과 DB 스키마를 유지한다.
- 감점 로직만 제거하면 rollback이 쉽다.

### 단점과 위험

- 코퍼스와 질문마다 점수 비율이 달라 전역 계수의 근거가 약하다.
- Q005를 해결하는 강한 감점은 제목 후보를 남기는 장점을 거의 없앤다.
- 향후 문서가 늘면 재튜닝이 필요하고, 임계값이 숨은 품질 정책이 된다.
- 낮아진 제목 후보가 여전히 Top 40과 RRF에 들어가 본문 후보 공간을 차지할 수 있다.

방식 A가 실제 본문 검색 목적에 맞지 않는 사례가 재평가에서 발견될 때만 예비 대안으로 검토한다.

## 9. Q003 시점 불일치 문제

Q003의 1위 00026은 제목-only가 아니므로 이번 mask의 제외 대상이 아니다. 원문은 진정 후 입원실 이동과 검사 중 모니터링을 설명하고, 질문은 “진정 전 준비사항”을 묻는다. 반면 관련 chunk 00015의 section과 본문에는 “진정 치료 전”이 명시돼 있다.

SCHAT 원시 점수는 00026이 0.785, 관련 00013이 0.698, 관련 00016이 0.669, 관련 00015가 0.657이다. 관련 근거가 Top 2~4에 있으므로 후보 회수보다 순서 결정 문제에 가깝다.

원인은 제목-only보다 다음에 가깝다.

- “진정”이 00026에서 여러 번 반복돼 BM25 점수가 높아졌다.
- 질문의 “전”은 한 글자이고 현재 lexical token으로 독립 반영되지 않는다.
- “준비사항”이라는 표현이 관련 본문에 그대로 없어서 의도·시점 일치가 원시 BM25 점수에 충분히 반영되지 않는다.

### 시점 처리 대안

| 대안 | 방식 | Q003 개선 가능성 | Hit@3 보존 | 기존 구조 영향 | 주요 위험 | 판단 |
|---|---|---:|---:|---|---|---|
| T1. 안정적 시점 tier 재정렬 | 기존 BM25 양수 후보를 요청 시점 일치, 시점 중립, 명시적 불일치 순으로 재정렬하고 각 tier 안에서는 기존 점수 순서를 유지 | 높음 | 높음. 후보를 삭제하지 않음 | 중간. 로컬·클라우드·평가 도구가 같은 ranking helper를 사용해야 함 | 시점 사전의 누락·오탐 | 후속 권고 |
| T2. BM25 score 가감 | 시점 일치 보너스와 불일치 감점을 원시 점수에 더하거나 곱함 | 중간~높음 | 중간~높음 | 낮음~중간 | 코퍼스마다 계수 재튜닝 필요 | 예비 대안 |
| T3. 현재 RAG rerank에서만 보정 | BM25+dense RRF 뒤 rerank_score에 시점 일치 신호 반영 | 최종 답변은 개선 가능하나 BM25 Hit@1은 그대로 | 높음 | 낮음 | BM25 단계의 관찰된 실패를 해결하지 못함 | BM25 개선안으로는 기각 |
| T4. chunk에 temporal_scope 저장 | 청킹 시 before/during/after metadata를 만들고 검색에서 사용 | 높음 | 높음 | 높음. Chunk·직렬화·DB migration·재색인 필요 | 원문 구조 추정 오류와 citation 영향 | 현재 범위에서 기각 |

### 후속 권고안: T1 안정적 시점 tier 재정렬

제목-only 방식 A의 재평가가 끝난 뒤 Q003이 계속 실패하면 T1을 별도 변경으로 승인받는다. tokenizer나 query 문자열을 바꾸지 않고 검색 순위 정책에서만 다음 정보를 파생한다.

- 요청 시점: original 또는 normalized query에서 “진정 전”, “시행 전”, “검사 전”, “투여 전” 등을 before로, 대응하는 “중”과 “후” 표현을 during과 after로 정규화한다.
- 후보 시점: chunk.text와 chunk.section에서 같은 제한적 표현을 찾는다. “진정 치료 전”처럼 중간 수식어가 있는 표현도 명시적 패턴으로 처리한다.
- 적용 조건: 질문에서 정확히 하나의 시점만 확인될 때만 적용한다. 시점이 없거나 둘 이상이면 기존 순서를 그대로 둔다.
- 우선순위: 요청 시점 포함 후보, 시점 표현이 없는 중립 후보, 다른 시점만 명시한 후보 순이다.
- 보존 조건: 후보를 삭제하지 않고 각 tier 내부의 기존 BM25 안정 정렬을 유지한다.

아래는 미구현 의사코드다.

```python
phase = requested_phase(query)  # lexical_tokens/query expansion은 변경하지 않음
rows = positive_bm25_candidates(scores, chunks)
if phase is not None:
    rows = stable_phase_rerank(rows, phase)
return rows[:limit]
```

이 정책에서는 00015·00016처럼 text 또는 section에 before가 명시된 관련 후보가 중립 또는 다른 시점 후보보다 앞선다. 00013처럼 시점 표현은 없지만 관련 있는 절차 후보는 제거하지 않아 Top 3 회수를 보호한다. Q006에는 시점이 없고 원시 점수도 모두 0이므로 후보 생성 전제에서 결과가 변하지 않아야 한다.

T1은 BM25Index의 점수 계산 책임과 분리한다. mvp/retrieval.py의 하나의 ranking helper가 로컬 검색, 클라우드 검색과 평가 도구에 공통 순서를 제공해야 하며, 호출자가 시점 규칙을 각각 재구현해서는 안 된다. 별도 서비스·설정 계층이나 자유로운 의료 동의어 사전은 만들지 않는다.

### Q003 검증 경계

- 제목-only 개선만 적용한 결과에서 Q003 순위를 먼저 기록한다. 이 결과가 우연히 바뀌어도 제목 mask의 직접 효과라고 단정하지 않는다.
- T1을 별도 승인·구현하면 00015 또는 00016을 첫 관련 결과 1위로 만드는 것을 목표로 한다.
- Q003의 관련 후보가 Top 3 밖으로 밀리지 않아야 한다.
- Q001·Q002·Q004·Q005처럼 시점이 없는 질문의 순서는 T1 적용 전과 같아야 한다.
- Q006의 모든 BM25 점수 0과 무관계 판정을 유지해야 한다.
- hard filter는 사용하지 않는다. 시점이 생략된 관련 문장을 제거하면 Hit@3 100%를 훼손할 수 있기 때문이다.

이번 제목-only 구현 범위에는 T1을 자동으로 포함하지 않는다. 제목-only와 시점 불일치는 원인·소유 정책·검증 기준이 다르므로 각각 결과를 확인하고 승인받는 두 개의 변경 단위로 유지한다.

## 10. 최종 설계 결정

방식 A를 선택한다. 구체적으로는 Chunk를 삭제하거나 다시 만들지 않고 BM25Index 내부에서 title-only mask와 다음 본문용 title context를 소유한다. 제목-only를 postings와 유효 BM25 문서 통계에서 제외하고 출력 점수 위치는 0으로 유지하며, 의미 있는 섹션 제목만 다음 본문의 색인 context로 사용한다.

선택 이유는 다음과 같다.

1. Q001·Q002·Q005의 관찰된 실패를 직접 제거한다.
2. 현재 관련 본문이 모두 2위라 Hit@1을 개선하면서 Hit@3를 유지할 가능성이 가장 높다.
3. 기존 chunk ID, 수동 label, 임베딩, DB 스키마와 citation을 보존한다.
4. 기존 BM25Index 호출자 서명을 바꾸지 않아 로컬·클라우드·평가 도구의 조정 비용이 작다.
5. 정책과 상태를 BM25Index에 모아 호출자가 내부 판정 규칙을 알 필요가 없다.
6. 점수 계수 튜닝이나 전면 재청킹 없이 rollback할 수 있다.

## 12. 검증 계획과 합격 기준

### 단위 테스트

- section과 동일한 단독 chunk는 title-only로 판정된다.
- 문서명·title과 동일한 단독 chunk는 title-only로 판정된다.
- 여러 PDF 페이지 첫 위치에 반복되는 짧은 표제는 title-only로 판정된다.
- 한 번만 나오는 짧은 임상 지시문과 문장형 본문은 제외되지 않는다.
- 명시적 section 제목은 같은 문서의 다음 검색 가능 본문 context로 한 번만 상속된다.
- running header, 문서 경계를 넘는 제목과 뒤에 본문이 없는 제목은 상속되지 않는다.
- BM25 scores 길이와 입력 chunks 길이는 동일하다.
- title-only 위치의 점수는 모든 query에서 0이다.
- 관련 본문의 점수는 0보다 크고 stable tie ordering 계약을 유지한다.
- 비어 있거나 전부 title-only인 코퍼스에서도 예외 없이 전부 0점을 반환한다.
- rank-bm25 경로에는 SCHAT mask나 점수 보정이 적용되지 않는다.

### 통합·회귀 테스트

- 로컬 검색의 dense/BM25 위치 매핑과 권한 문서 범위를 유지한다.
- 클라우드 캐시의 chunks와 BM25 scores 위치가 일치한다.
- 기존 rerank, context 확장, citation의 chunk ID·page/location이 바뀌지 않는다.
- Q006은 두 엔진 모두 양의 BM25 점수를 만들지 않는다.
- 기존 전체 테스트를 실행하고 기존 정상 검색·권한·출처 검증이 모두 통과한다.

### 동일 평가셋 재평가

기존 결과를 덮어쓰지 않고 새 artifacts 디렉터리에 다음을 생성한다.

- SCHAT BM25Index Top 10
- 변경하지 않은 rank-bm25 Top 10
- CSV, JSON, review.html
- 기존 72개 label을 chunk ID로 재적용한 지표
- title-only 노출 빈도와 질문별 순위 변화

합격 기준은 다음과 같다.

1. 판정 대상 72/72 연결을 유지한다.
2. Q001·Q002·Q005에서 제목-only가 1위가 아니다.
3. Q001의 00003과 Q005의 00028이 각각 1위가 되는 것을 목표로 한다.
4. 양성 질문 Hit@1은 최소 80%를 목표로 한다.
5. 양성 질문 Hit@3·5·10은 100%를 유지한다.
6. Q004의 기존 1위를 유지한다.
7. Q006의 모든 SCHAT BM25 점수는 0을 유지한다.
8. SCHAT 양성 Top 10의 제목-only 노출은 13/50에서 0/50을 목표로 한다.
9. Q003은 별도 실패로 남겨 순위와 원인을 숨기지 않는다.

Q002는 하나의 chunk로 전체 절차를 완성할 수 없는 multi-chunk 질문이므로 별도 기준을 함께 적용한다.

1. 첫 관련 chunk가 1위인지 기록한다. 00013 단일 ID만을 성공의 충분조건으로 삼지 않는다.
2. Top 3의 절차 관련 chunk 수와 substantive 본문 수를 각각 기록한다.
3. Top 5에 진정 전 확인·평가, 동의, 투약, 진정 중 모니터링, 진정 후 회복·퇴실 중 서로 다른 단계가 몇 개 포함되는지 원문 기준으로 기록한다.
4. Top 5에 최소 2개의 서로 다른 절차 단계가 substantive 본문으로 회수되는 것을 충분 회수의 최소 기준으로 삼는다.
5. 제목-only chunk가 첫 substantive 절차 본문보다 앞서지 않아야 한다.
6. partially_relevant 제목-only 00042는 관련 label 통계에는 유지하지만 substantive 절차 단계 수에는 포함하지 않는다.

목표를 충족하지 못하면 tokenizer나 query expansion을 즉시 변경하지 않는다. 먼저 mask 오분류와 BM25 문서 통계 변화를 분석하고 결과 문서에 실패를 그대로 기록한다.

## 13. 구현 순서

사용자 승인 후에만 다음 순서로 진행한다.

1. 평가 코퍼스의 7개 제목-only와 보존해야 할 짧은 본문을 테스트 fixture로 고정한다.
2. mvp/retrieval.py에 corpus 순서와 같은 검색 가능 mask와 inherited title context 판정을 구현한다.
3. BM25Index가 제외 문서를 postings·평균 길이·IDF 유효 문서 수에서 빼고 명시적 제목을 다음 본문 색인 context로 사용하되 scores 위치 계약을 유지하도록 변경한다.
4. SEARCH_VERSION을 증가시켜 새 검색 정책과 이전 캐시 범위를 구분한다.
5. 단위 테스트와 로컬·클라우드 검색 회귀 테스트를 실행한다.
6. 기존 원본과 2026-09-12 산출물을 건드리지 않고 새 디렉터리에 두 엔진 결과를 생성한다.
7. 72개 label을 재사용해 Hit@k, MRR, 제목-only 빈도와 Q001~Q006 순위를 계산한다.
8. docs/bm25/04_TITLE_CHUNK_IMPROVEMENT_RESULT.md에 전후 결과와 BM25 단계 승인 권고를 작성한다.
9. 작업을 멈추고 사용자 승인을 기다린다. 승인 전에는 RAG 단계로 넘어가지 않는다.

## 14. Rollback

권고안은 영속 chunk와 DB를 바꾸지 않으므로 rollback은 코드 단위다.

1. mvp/retrieval.py의 BM25 corpus policy, 제목 context 상속과 후보 제외 처리를 되돌린다.
2. SEARCH_VERSION을 이전 값으로 되돌린다.
3. 해당 변경을 위해 추가한 테스트만 함께 되돌린다.
4. 새 개선 실험 artifacts와 결과 문서는 이전 2026-09-12 기준 결과와 섞지 않는다.

원본 문서, 기존 chunk ID, 임베딩, Supabase 데이터와 2026-09-12 평가 산출물은 rollback 대상이 아니며 처음부터 수정하지 않는다.

## 15. 위험과 확인 사항

- 반복 페이지 표제 규칙이 짧은 실제 지시를 오분류하지 않는지 다양한 PDF fixture가 필요하다.
- 현재 1개 문서·6개 질문 결과만으로 일반화할 수 없으므로 향후 다른 지침서의 제목 구조도 별도 검증해야 한다.
- title-only가 dense 후보로만 들어오는 경우 최종 rerank에서 제거되는지 로컬·클라우드 양쪽을 확인해야 한다.
- Q002의 00042는 사람이 partially_relevant로 판정했지만 본문 없는 제목이다. Hit 계산에서는 관련으로 취급했던 기존 규칙을 유지하되, 단독 답변 근거로 사용하지 않는 정책과 구분한다.
- Q003 시점 불일치는 이번 변경의 합격 여부와 별도로 기록하며 후속 설계 승인 없이는 수정하지 않는다.

## 16. 사용자 승인 대기

이 계획 작성으로 작업을 멈춘다. 권고안은 “제목-only chunk를 저장 코퍼스에서는 유지하되 SCHAT BM25Index의 독립 lexical 후보에서 제외”하는 방식이다. 구현, 테스트 산출물 생성, tokenizer·query expansion 변경, rank-bm25 교체와 RAG 작업은 사용자의 명시적 승인 후에만 진행한다.
