# SCHAT Final MVP Completion Design

## Status and authority

- Stable recovery point: annotated tag `v0.8`.
- Working branch: `boha-rag`.
- The user approved unattended analysis, implementation, and verification, but did not approve Git commit, tag, push, external provider calls, hospital-data transmission, or clinical image interpretation.
- Existing validators, Facet-slot selection, selection limit 16, parent atomicity, Q006 zero-call, and the production retrieval contract remain fail-closed.

## Scope

This milestone closes the remaining locally verifiable gaps without pretending that an unapproved provider or an unreviewed diagram has been validated. It has four independently testable tracks:

1. Reranker bottleneck diagnosis and retrieval strategy decision.
2. Structured-table numeric retrieval correction and local table UAT.
3. Controlled-generation fallback/validation contract and answer-style regression.
4. Multimodal/image metadata safety, multi-document architecture tests, performance/security audit, and project-state documentation.

## Retrieval design

The frozen comparison contract remains the 105 transfusion chunks, 90 questions, 78 approved positive questions, 11 negative questions, one human-review exclusion, and Top-K 1/3/5/10. Gold IDs are used only after ranking to calculate metrics.

The evaluator compares:

- current BM25;
- E5-only;
- raw BM25+E5 RRF;
- the current reranker;
- normalized-input reranking;
- candidate-origin-aware reranking;
- rank-preserving reranking;
- top-N-only reranking;
- a bounded origin-feature reranker.

All experimental rerankers consume only query plan, rank, retrieval origin, and candidate metadata/text. They cannot consume question IDs, gold IDs, or fixture labels. A production change is allowed only if a candidate improves the frozen accuracy score without losing Hit@10/Recall@10, keeps Q006 and validators unchanged, and has acceptable local latency/memory. Otherwise production remains `BM25 + MiniLM semantic/vector + RRF + reranker`.

If E5 is not adopted, no production vector-store change is made. For the current 105-chunk evaluation, the existing raw-free NumPy snapshot remains the reference because it loads quickly and avoids a new dependency. ChromaDB/Qdrant are not added merely for technology preference.

## Table design

MM003 is already human-approved structural-table gold. Offline inspection shows its gold is linked to page-2 row 10, but the current scorer counts all lexical tokens equally; a distractor row with more generic Korean token overlap outranks the exact numeric/time row.

The table-only scorer will therefore classify tokens and apply fixed, query-independent weights:

- exact number+unit/time token: highest weight;
- full lexical/entity token: normal weight;
- Korean two-character helper n-gram: low weight.

Header inheritance, row identity, source-chunk links, citation metadata, and exact cell values remain unchanged. The change is validated first with a synthetic numeric distractor test, then MM001-MM005. No question string, chunk ID, table ID, or gold ID is added to production scoring.

The current catalog does not store table cells/geometry as a production entity, and the cloud repository has no table schema. Connecting structured table evidence to the main answer path would require a cross-backend ingestion/storage migration. That is a large production-structure change and is outside this safe milestone. The local table evaluation UI remains the supported UAT surface; the final report will mark production table ingestion as pending rather than silently parsing originals at query time.

## Controlled generation design

The provider-neutral schema, request-scoped SourceUnit IDs, citations regenerated by the server, number/unit/condition/negation/branch/phase checks, and evidence coverage remain.

This milestone adds an explicit decision boundary:

- schema or invariant failure: no retry, use the already validated extractive Answer;
- semantic support pending: do not publish paraphrased clinical text; use the extractive Answer;
- only a future approved semantic-support validator may mark controlled text publishable.

Formatting-only presentation continues through the metadata sidecar. No clinical text is automatically repaired, truncated, deduplicated, reordered, or supplemented.

## Image and multimodal design

Figure inventory, bbox, caption/nearby-text hashes, type, confidence, fingerprint, and routing metadata may be produced locally. Image-derived arrows, order, numbers, units, branches, or clinical meaning are never inferred. TF027 remains `needs_human_review=true`; image queries remain safely pending rather than being answered from unapproved interpretation.

Routing remains conditional: text by default, table+text for structured numeric/comparison questions, and pending image-only for explicit workflow/figure requests. It does not relax evidence admission or answerability.

## UAT, scaling, and security

- Text web UAT uses synthetic/fixture-backed verified Answers and never calls a provider.
- Table web UAT uses the local evaluation app and keeps exact table text in memory only.
- Multi-document tests cover document filters, same-topic isolation, source conflict metadata, and stable IDs without adding a third hospital document.
- Performance records retrieval/reranker/table/assembly latency and existing E5 snapshot load/model memory.
- Artifacts contain IDs, scores, counts, hashes, timings, and decisions only; no source text, prompt, provider response, authorization value, or secret.

## Completion and pending boundaries

The milestone is an approval-waiting final MVP candidate when all offline tests and audits pass. Provider Live, semantic entailment, production table-storage migration, and image clinical interpretation remain explicitly pending. The next version is proposed as `v0.9`; no commit/tag/push occurs without user approval, and `v0.8` is never moved.
