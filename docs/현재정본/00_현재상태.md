## 최종 목표

병원 실무지침서를 등록하면 간호사가 자연어로 질문하고, SCHAT가 지침 안의 정확한 근거를 찾아 읽기 쉽게 답하며, 출처와 표·도식까지 함께 보여주는 웹앱을 만든다. 지침에서 충분한 근거를 찾지 못하면 임의로 답하지 않고 안전하게 멈추는, 병원 지침용 NotebookLM 형태가 목표다.

## 현재 Production

실제 서비스 경로는 다음 구조를 유지한다.

```text
질문
  → QueryPlan/도메인·의도 분석
  → BM25 + MiniLM semantic/vector 후보
  → RRF
  → 기존 reranker
  → evidence gate와 Facet-slot SourceUnit 선택
  → 서버 reconstruction
  → validate_answer()와 citation 검증
  → presentation sidecar 기반 Streamlit UI
```

- Retrieval: `BM25 + semantic/vector + RRF + reranker`
- Production embedding: `sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2`, 384 dimensions
- E5-large: evaluation-only, production 미사용
- ChromaDB: evaluation-only, production 미사용
- Facet-slot selection limit: 서로 다른 SourceUnit 최대 16개
- Provider: 승인된 설정에서 Groq SourceUnit 선택 경로를 지원한다. 이번 최신 통합 평가는 Groq/Gemini/vision 호출 0회였다.
- Controlled generation: Mock/validator까지만 있으며 production provider와 미연결
- Table/image routing: production answerability에 미연결

## 최근 변경사항

- 수혈 105 chunks와 승인된 positive 78문항을 기준으로 BM25, MiniLM, E5-large, RRF, reranker, selective fallback을 같은 조건에서 비교했다.
- E5-large 단독과 `BM25 + E5 RRF`의 raw retrieval 정확도 향상을 확인했다.
- 기존 reranker를 E5 조합에 적용하면 이득이 작아지는 현상을 확인했다.
- 정확도 이득보다 지연·메모리·reranker 회귀 위험이 커, production 검색 구조는 바꾸지 않았다.
- 검증된 답변을 바꾸지 않는 presentation sidecar와 질문 유형별 표시 형식을 통합 회귀로 확인했다.
- controlled paraphrasing은 provider-neutral schema/prompt/Mock validator까지 준비했다.
- 표 5개, 33개 행의 evaluation-only 검색·인용·로컬 UI를 검증했다.
- 이미지/도식은 TF027 사람 검수 전까지 pending으로 유지했다.

## 변경하지 않은 영역

- Production BM25, MiniLM semantic/vector, RRF, reranker
- Production embedding과 catalog vector
- Facet-slot, SourceUnit, selection limit 16
- Parent atomicity, PromptCoverage, AnswerCoverage
- `validate_answer()`와 citation·number·unit·time·condition·negation·action·source-order validator
- Q006 out-of-scope zero-call 경계
- Production dependency와 generation provider 설정
- Retry, fallback, web search 정책

## 현재 남은 작업

1. Existing reranker가 E5 semantic candidate의 순위를 낮추는 원인을 evaluation-only로 분석한다.
2. 병원 데이터 외부 전송 정책과 provider 사용이 별도 승인된 뒤 controlled generation Live와 semantic entailment를 평가한다.
3. TF027 workflow를 사람이 검수하고, 승인된 image-dependent gold가 생긴 뒤 image/vision 평가를 시작한다.
4. Table miss `MM003`의 gold/row 연결을 검토하고 production table 연결의 명확한 이득을 다시 판단한다.
5. 다음 major 작업은 `v0.8`을 기준으로 시작하고 완료 후 현재정본과 다음 복구 기준점을 갱신한다.

## AGENTS.md 관리 규칙 추가 제안

기존 규칙을 삭제하지 않고 다음을 추가하는 것이 좋다. 이번 문서 정리에서는 `AGENTS.md`를 수정하지 않는다.

- major 기능 변경 후 `docs/현재정본/`을 반드시 갱신한다.
- 현재정본은 항상 실제 production 코드와 일치해야 한다.
- 과거 기록은 현재정본에 누적하지 않고 상세 기록 폴더에 남긴다.
- major 기능 완료 후 `변경이력.md`와 `복구기준점.md`를 갱신한다.
- 큰 작업 전 마지막 안정 commit을 확인한다.
- major milestone 후 안정 복구 기준점 후보를 기록한다.
- 사용자 승인 없이 commit, tag, push하지 않는다.
- 완료 순서는 `테스트 → 현재정본 → 변경이력 → 복구기준점 → progress`로 한다.
