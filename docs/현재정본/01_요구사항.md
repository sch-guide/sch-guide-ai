# SCHAT 현재 요구사항

## 제품 목표

병원 실무지침서를 등록하면 간호사가 자연어로 질문하고, SCHAT가 지침 안의 근거만 사용해 읽기 쉬운 답변과 출처를 제공한다. 근거가 부족하거나 범위를 벗어나면 추측하지 않고 안전하게 답변을 중단한다.

## 필수 기능

1. PDF·DOCX·XLSX 등록과 안정적인 document/chunk ID 생성
2. 자연어 질문의 domain, topic, aspect, phase, branch, intent 분석
3. BM25와 semantic/vector 후보를 RRF와 reranker로 결합
4. Parent atomicity, PromptCoverage, AnswerCoverage와 Facet-slot SourceUnit selection
5. 서버 reconstruction과 문장/항목별 citation
6. 질문 유형별 paragraph, step, checklist, warning, comparison, summary UI
7. 구조화된 표의 row 검색과 document/page/table/row citation
8. 이미지/도식은 승인된 metadata와 사람 검수 경계 안에서만 사용
9. 근거 부족/out-of-scope 질문의 provider zero-call abstention
10. 여러 문서의 filter, branch, conflict와 source identity 보존

## 유지해야 하는 안전 계약

- Facet-slot과 distinct selection limit 16
- Answer statement limit 16
- Parent atomicity
- PromptCoverage와 AnswerCoverage
- `validate_answer()` 전체
- Exact citation/source sentence
- Number, unit, time, condition, contraindication, negation, action
- Branch, phase, source order, duplicate evidence
- Q006 provider transport 0회
- 자동 truncation, ID 제거·보충·dedup·재정렬 금지

## Retrieval 요구사항

- Production은 현재 `BM25 + MiniLM semantic/vector + RRF + existing reranker`다.
- 새 전략은 동일 corpus/chunk ID/query/gold/Top-K/metric의 evaluation을 먼저 통과해야 한다.
- Gold, question ID, chunk ID를 production scoring에 하드코딩하지 않는다.
- E5-large와 BM25+E5 RRF는 evaluation-only이며 production model/dependency를 바꾸지 않는다.
- Vector DB는 embedding model과 별개로 판단하며 실익이 없으면 추가하지 않는다.

## Generation 요구사항

- 현재 production Answer는 verified extractive reconstruction이다.
- Controlled paraphrase는 request-scoped SourceUnit ID만 참조하고 server citation을 재생성해야 한다.
- Schema/invariant/semantic support 중 하나라도 미확정이면 retry 없이 기존 extractive Answer를 사용한다.
- 임상정보, 숫자, 시간, 용량, 조건, 금기, 부정, action, branch, phase를 새로 만들거나 바꾸지 않는다.
- 승인된 semantic validator와 외부 전송 정책 전에는 controlled candidate를 사용자에게 공개하지 않는다.

## Table 요구사항

- Table ID, document/page, row/column, header/cell, bbox, fingerprint를 보존한다.
- PDF cell extraction이 sparse하면 기존 substantive catalog parent rows로만 fallback한다.
- 숫자·단위·시간 exact match는 helper n-gram보다 우선한다.
- Local evaluation UI만 exact row text를 표시하며 artifact에는 ID/hash/좌표만 저장한다.
- Production persistence는 Local/Cloud repository schema가 함께 설계·검증된 경우에만 연결한다.

## Image 요구사항

- 로고·장식은 제외하고 figure ID, document/page, bbox, caption, nearby text, type, confidence, fingerprint를 기록한다.
- 화살표 방향, workflow 순서, 숫자·단위, decision branch를 사람 검수 없이 확정하지 않는다.
- 불확실하면 `needs_human_review=true`다.
- TF027은 승인 전 production gold로 사용하지 않는다.

## 보안·운영 요구사항

- 병원 원문의 외부 API 전송 금지
- API key, Authorization header, 전체 prompt, raw provider response 저장 금지
- Exact SourceUnit 대량 artifact 저장 금지
- Major 변경마다 focused test, full pytest, Ruff, `git diff --check`, code review, artifact audit 수행
- 사용자 승인 없이 commit, tag, push 금지
- 공식 안정 tag `v0.8` 보존
