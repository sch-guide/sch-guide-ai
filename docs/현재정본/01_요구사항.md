# SCHAT 현재 요구사항

> 과거 요구사항을 누적한 문서가 아니라, 지금 SCHAT가 최종적으로 만족해야 하는 기능과 안전 조건의 정본이다.

현재 `AGENTS.md`가 참조하는 `docs/PRD.md`는 저장소에 존재하지 않는다. 따라서 이 문서를 현재 요구사항의 사용자용 정본으로 사용하고, 추후 `AGENTS.md`의 참조 경로를 바꾸는 일은 별도 승인 후 진행한다.

## 제품 목표

병원 실무지침서를 등록하고 간호사가 자연어로 질문하면, 문서 안의 근거만 사용해 정확하고 읽기 쉬운 답변과 출처를 제공한다. 표와 도식도 안전하게 활용하고, 근거가 부족하면 답하지 않는다.

## 핵심 기능

1. **병원 실무지침서 등록**
   PDF·DOCX·XLSX 등 승인된 지침을 기존 ingestion/chunking 규칙으로 등록하고 문서·페이지·section·parent 관계를 보존한다.
2. **자연어 질문**
   띄어쓰기, 구어체, 목적·절차·준비·주의·시간·대상 표현을 일반화해 해석한다.
3. **정확한 근거 검색**
   Production의 BM25와 의미 검색을 결합하고 RRF와 reranker를 거쳐 후보를 찾는다.
4. **근거 기반 답변**
   선택된 SourceUnit만 사용하고 서버가 원문과 출처를 재구성한다.
5. **출처 표시**
   문장이나 항목별로 문서, 페이지·위치, chunk 근거를 확인할 수 있어야 한다.
6. **표 검색**
   표의 header와 row 관계, 숫자와 단위를 보존한 검색·인용을 제공해야 한다.
7. **이미지·도식 처리**
   flowchart, algorithm, decision tree처럼 임상 의미가 있는 그림만 대상으로 하며 불확실하면 사람 검수를 요구한다.
8. **근거 부족 시 답변 차단**
   out-of-scope, 불충분 evidence, validator 실패에서는 provider 호출이나 답변을 안전하게 차단한다.
9. **원본 페이지 확인**
   사용자가 출처에서 원문 위치를 확인할 수 있어야 한다.
10. **다중 문서 지원**
    진정간호와 수혈간호처럼 여러 지침을 함께 등록하되 문서 ID, chunk ID, 권한과 출처를 섞지 않는다.

## 검색 요구사항

- 현재 production 검색 구조는 `BM25 + MiniLM semantic/vector + RRF + reranker`다.
- 검색 전략 변경은 동일 corpus, 동일 chunk ID, 동일 질문/gold, 동일 Top-K와 metric의 평가 결과가 있어야 한다.
- E5-large와 ChromaDB는 현재 evaluation-only다.
- 질문 문자열, chunk ID, gold를 production scoring에 하드코딩하지 않는다.
- Parent 단위 evidence는 부분 포함하지 않고 atomicity를 유지한다.
- Negative/out-of-scope 질문은 positive retrieval 평균과 분리해 진단한다.

## 답변 요구사항

- SourceUnit 선택과 Answer statement의 최대 개수는 각각 16개를 유지한다.
- 검증된 evidence 밖 임상 정보를 추가하지 않는다.
- 답변 스타일은 질문에 맞게 문단·단계·checklist·주의 bullet·비교표·전/중/후·성인/소아 구조를 사용할 수 있다.
- 자연스러운 재서술을 사용하더라도 숫자, 단위, 시간, 조건, 금기, 부정, 행동, branch와 phase를 바꾸지 않는다.
- Citation은 서버가 evidence identity에서 다시 생성하고 전체 validator를 통과해야 한다.
- 자동 truncation, ID 제거, 보충, dedup, 재정렬로 validator를 우회하지 않는다.

## 안전 요구사항

- 병원 지침 밖의 정보를 임의 생성하지 않는다.
- 숫자·단위·시간·조건·부정·금기·행동을 검증한다.
- Citation, source sentence, source order, duplicate evidence와 AnswerCoverage를 검증한다.
- 충분한 근거가 없으면 고정 abstention을 반환한다.
- Q006 같은 out-of-scope 질문은 provider transport 0회를 유지한다.
- API key, Authorization header, 전체 prompt와 raw provider response를 저장하지 않는다.
- 병원 원문 전체나 대량의 exact SourceUnit text를 artifact/Git에 저장하지 않는다.
- 병원 데이터의 외부 provider 전송은 사용자와 정책의 명시적 승인 없이는 수행하지 않는다.

## 표 요구사항

- `table_id`, document/page, row/column, header, cell, bbox, fingerprint 관계를 보존한다.
- 표 전체, row, header+row, key-value 단위 검색을 평가할 수 있어야 한다.
- Header/cell 관계와 값을 추측하지 않는다.
- 표 인용에는 문서, 페이지, table ID와 row가 포함돼야 한다.
- 표가 유일한 근거인 질문도 평가하되, production 연결은 명확한 개선과 회귀 검증 후 승인한다.

## 이미지·도식 요구사항

- 장식 이미지는 제외한다.
- figure ID, document/page, bbox, caption, nearby text, type, confidence와 fingerprint를 보존한다.
- 화살표 방향, workflow 순서, 숫자·단위가 불명확하면 `needs_human_review=true`로 둔다.
- 승인된 image-dependent gold 없이 vision 경로를 production 근거로 사용하지 않는다.
- 외부 vision API 호출과 병원 데이터 전송은 별도 승인이 필요하다.

## 사용자 화면 요구사항

- 질문 입력창
- 읽기 쉬운 답변
- 문장/항목별 출처
- 근거 보기
- 표 보기
- 원본 페이지 보기
- 관련 지침 보기
- 근거 부족 안내
- 관리자용 문서 등록·검색 진단

## 운영·검증 요구사항

- major 변경마다 관련 집중 테스트와 전체 pytest를 실행한다.
- Ruff, `git diff --check`, code review와 artifact security audit를 통과한다.
- UAT는 개별 질문 하드코딩 대신 질문 유형별 일반화를 평가한다.
- 현재정본은 production 코드와 일치하게 유지한다.
- 사용자 승인 없이 Git commit, tag, push하지 않는다.

## 버전 체계

과거 commit에는 임의 tag를 붙이지 않는다. `v0.8`부터 안정 milestone마다 annotated tag를 사용한다.

| tag | 의미 |
|---|---|
| `v0.8` | 현재 text/table MVP 안정 기준점 — 저장 완료 |
| `v0.9` 제안 | 승인된 provider generation과 image/multimodal 검증 완료 |
| `v1.0` 제안 | 실사용 MVP 승인 완료 |

새 tag 생성과 push는 매번 사용자 승인 후에만 한다.
