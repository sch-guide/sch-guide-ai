# SCHAT 전체 구조

## Production 흐름

```text
Streamlit 질문
  → QueryPlan(domain/topic/aspect/phase/branch/intent/evidence candidates)
  → BM25 + MiniLM semantic/vector candidate generation
  → RRF + existing reranker
  → context expansion + parent atomicity
  → pre/post evidence gate
  → Facet-slot SourceUnit contract
  → provider selection 또는 zero-call
  → server reconstruction
  → AnswerCoverage + validate_answer()
  → presentation sidecar
  → 답변/출처/근거 UI
```

## Trust boundaries

- Retrieval score는 answerability나 임상 사실을 직접 만들지 않는다.
- Provider는 request-scoped ID만 선택하며 text/quote/chunk metadata는 서버가 복원한다.
- Presentation sidecar는 검증된 Answer text와 citation을 변경하지 않는다.
- Controlled generation candidate는 semantic support가 미확정이면 공개하지 않는다.
- Table exact text는 로컬 메모리에만 존재하고 raw-free artifact에는 포함하지 않는다.
- Image routing은 answerability에 연결되지 않으며 human review pending이다.

## Multi-document 확장

- 모든 chunk, parent, evidence, citation은 document ID를 포함한다.
- Context expansion은 seed와 같은 document/parent 경계를 벗어나지 않는다.
- Requested document filter는 repository/search에서 적용된다.
- 서로 다른 문서의 충돌은 양쪽 citation을 요구하며 임의로 합치지 않는다.
- 동일 keyword의 다른 의미는 topic/aspect/section/parent metadata로 분리한다.

## 저장 구조

- Production catalog: SQLite/local 또는 승인된 cloud repository
- Production vector: 현재 MiniLM catalog vector
- E5 snapshot: raw-free NumPy evaluation cache, production 미사용
- Table structure: 현재 evaluation-time memory object; production schema 미추가
- Figure: raw-free metadata manifest만 유지
