# SCHAT 전체 구조

## 한눈에 보는 흐름

```text
간호사 질문
  ↓
질문 분석: domain · topic · aspect · phase · branch · evidence type 후보
  ↓
검색: BM25 + MiniLM semantic/vector
  ↓
결합·정렬: RRF + 기존 reranker
  ↓
근거 gate: topic/aspect/semantic block/parent atomicity/coverage
  ↓
Facet-slot SourceUnit 선택: 필요한 근거 ID만 provider가 선택
  ↓
서버 reconstruction: exact text · quote · chunk ID 복원
  ↓
validate_answer(): citation · 숫자 · 단위 · 시간 · 조건 · 부정 · 행동 · 순서
  ↓
presentation sidecar: 검증된 답변은 바꾸지 않고 화면 구조만 지정
  ↓
Streamlit UI: 답변 · 출처 · 근거 · 원본 위치
```

근거 gate에서 부족하다고 판단하면 provider를 호출하지 않고 안전하게 답변을 차단한다.

## 단계별 구조

| 단계 | 역할 | 현재 상태 | 주요 파일 |
|---|---|---|---|
| 설정 | 실행 모드, embedding, provider, 제한값을 읽음 | 운영 중 | `mvp/settings.py` |
| 문서 등록 | 원문을 읽고 기존 규칙으로 chunk·metadata·embedding을 생성 | 운영 중 | `mvp/library.py`, `mvp/parse.py`, `mvp/storage.py` |
| 질문 분석 | domain, intent, topic, aspect, temporal/branch qualifier를 계획 | 운영 중 | `mvp/query.py` |
| BM25 검색 | 같은 용어가 있는 chunk를 빠르게 후보화 | 운영 중 | `mvp/retrieval.py`, `mvp/library.py` |
| 의미 검색 | MiniLM embedding으로 의미가 가까운 후보를 검색 | 운영 중 | `mvp/library.py`, storage adapter |
| 후보 결합 | BM25와 의미 후보를 RRF로 병합 | 운영 중 | `mvp/retrieval.py` |
| 재정렬 | topic·phase·lexical 규칙으로 후보 우선순위를 조정 | 운영 중 | `mvp/retrieval.py` |
| Context 확장 | parent를 원자적으로 포함하고 부분 block을 차단 | 운영 중 | `mvp/context.py` |
| Evidence 평가 | PromptCoverage/AnswerCoverage와 근거 충분성을 검사 | 운영 중 | `mvp/evidence.py` |
| SourceUnit catalog | 선택 가능한 최소 원문 단위를 만들고 metadata를 보존 | 운영 중 | `mvp/evidence.py` |
| Facet-slot 선택 | request별 필수 facet마다 허용 SourceUnit ID 하나를 선택 | 운영 중 | `mvp/ai.py`, `mvp/evidence.py` |
| Reconstruction | 선택 ID를 exact statement/quote/chunk citation으로 복원 | 운영 중 | `mvp/ai.py` |
| Answer 검증 | 근거·수치·의미·순서·coverage를 fail closed로 검증 | 운영 중 | `mvp/ai.py`, `mvp/evidence.py` |
| Presentation | branch/phase/스타일 metadata를 Answer와 분리해 생성 | 운영 중 | `mvp/presentation.py` |
| 답변 UI | 검증된 statement와 출처를 읽기 쉽게 표시 | 운영 중 | `mvp/answer_ui.py`, `mvp/app.py` |
| Controlled generation | 제한된 재서술 schema/prompt/Mock 검증 | 개발 중, provider 미연결 | `mvp/controlled_generation.py` |
| Table evidence | 표 구조화·행 검색·인용·로컬 UI | 평가 완료, production 미연결 | `tools/structured_table_evidence.py`, `tools/table_evidence_app.py` |
| Evidence routing | text/table/image/mixed 후보 metadata 생성 | 개발 중, answerability 미연결 | `mvp/evidence_routing.py` |
| Image/vision | figure metadata와 검수 경계 | 사람 검수 필요 | evaluation artifacts와 fixture |

## 저장 데이터

- Production catalog는 문서, chunk, page, section, parent, embedding과 안정 ID를 보존한다.
- 현재 등록 기준은 진정간호 42 chunks와 수혈간호 105 chunks다.
- Local catalog 파일은 `data/library/catalog.sqlite3`이며 기존 Git 관리 범위에 포함되어 있다.
- 원문 PDF와 민감한 병원 내용은 공개 artifact로 복제하지 않는다.

## Provider와 외부 통신

- 기존 SourceUnit 선택 경로는 승인된 Groq 설정에서 동작할 수 있다.
- Gemini adapter와 vision production 경로는 현재 없다.
- 최신 retrieval·multimodal 통합 검증에서는 외부 generation/vision API 호출이 0회였다.
- 병원 데이터 외부 전송은 별도 정책·사용자 승인이 필요하다.

## 현재 구조에 포함되지 않은 것

- Production ChromaDB
- Production E5-large
- E5 vector snapshot의 서비스 로딩
- Table evidence의 production answerability 연결
- Image/vision 임상 해석
- Controlled generation의 실제 provider 연결
