# SCHAT 검색 구조

## 최종 Production 판정

Production retrieval은 **BM25 + MiniLM semantic/vector + RRF + existing reranker**를 유지한다.

동일 수혈 105 chunks, 90문항, approved positive 78문항에서 BM25+E5 raw RRF가 가장 정확했지만, E5는 약 1.54 GB RSS와 평균 약 193 ms query embedding 비용이 필요하다. 기존 reranker는 E5 후보에 적용할 때 raw RRF의 recall과 MRR을 낮췄다. 안전 reranker를 우회하거나 대규모 production 구조를 바꿀 만큼 운영 이득이 명확하지 않아 production 변경을 하지 않았다.

## Reranker 병목

- Raw RRF Top-10은 높은 recall을 갖는다.
- Existing reranker는 Top-40에서 lexical/coverage 중심으로 다시 선택하면서 일부 E5 semantic candidate를 Top-10 밖으로 밀어낸다.
- Candidate-aware와 rank-preserving 변형은 raw Top-10 identity를 보존해 recall 손실을 막는다.
- 그러나 항상 E5를 실행하는 지연·메모리 비용은 남는다.
- Gold ID, question ID, query 문자열 특례는 ranking 입력에 사용하지 않았다.

## Vector storage 판정

E5를 production에 채택하지 않았으므로 ChromaDB/Qdrant dependency를 추가하지 않는다.

- Evaluation snapshot: 105×1024 vectors, 389,672 bytes
- Snapshot load: 11.46 ms
- Passage re-embedding: runtime마다 필요 없음
- E5 model cache: 약 2.25 GB

현재 평가 규모에서는 raw-free persisted NumPy snapshot으로 충분하다. 수천/수만 chunks로 확대하고 E5 production 채택이 확정될 때 별도 vector DB를 재평가한다.

## 유지 경계

- Parent atomicity와 evidence gate 완화 없음
- Facet-slot/validator 변경 없음
- BM25/RRF/reranker production semantics 변경 없음
- Q006 out-of-scope zero-call 유지
