# SCHAT 답변 생성

## 현재 Production

Provider가 선택한 SourceUnit을 server가 다음처럼 복원한다.

- `Statement.text = SourceUnit.exact_text`
- `Evidence.quote = SourceUnit.exact_text`
- `Evidence.chunk_id = SourceUnit.chunk_id`

그 뒤 AnswerCoverage와 `validate_answer()` 전체를 통과한 Answer만 UI에 전달한다.

## Controlled generation

- Groq/Gemini 공통 offline contract와 Mock validator가 준비돼 있다.
- 공통 evidence, instruction, JSON schema를 쓰고 provider별 wire envelope만 다르다.
- Citation, number, unit, time, condition, negation, action, branch, phase, coverage를 server가 재검증한다.
- Semantic support가 미확정이면 publish하지 않고 extractive fallback을 사용한다.
- 이번 최종 검증에서 실제 Groq/Gemini 호출은 각각 0회다.

## Live pending 사유

다음 승인이 명시적으로 확인되지 않았다.

1. 병원 evidence exact text 외부 전송 정책
2. provider/model/region/retention 조건
3. 허용 case와 provider별 호출 상한

따라서 최종 provider 판정은 `E — 외부 전송 승인 부재로 Live 미평가`다.

## Gold와 RAGAS

- Generated answer가 없으므로 Faithfulness와 Answer Relevancy는 pending이다.
- 운영 positive Gold 32건은 사람의 mapping/critical-fact 승인 전 provisional이다.
- Provider candidate가 semantic/citation/number/unit/time/condition/negation/action/branch/phase/
  AnswerCoverage 중 하나라도 실패하면 공개하지 않고 verified extractive answer로 fallback한다.

## Presentation

Presentation sidecar는 statement index, SourceUnit ID, branch, phase, source order, leading marker만 사용한다. 임상 문장을 새로 만들거나 citation을 변경하지 않는다.
