# SCHAT 답변 생성

## 현재 Production 답변 계약

현재 답변은 모델이 자유롭게 임상 문장을 쓰는 방식이 아니다.

1. Evidence gate가 통과한 request-local SourceUnit catalog를 만든다.
2. Facet-slot schema가 필수 facet마다 허용된 SourceUnit ID 하나를 선택하게 한다.
3. 서버가 ID를 exact `Statement.text`, `Evidence.quote`, `chunk_id`로 복원한다.
4. 기존 `validate_answer()`와 coverage/citation validator를 모두 다시 실행한다.
5. 검증이 끝난 뒤에만 metadata-only presentation sidecar를 붙인다.
6. UI는 statement를 바꾸지 않고 제목·단계·목록과 출처를 표시한다.

Provider가 text, quote, chunk ID, branch, phase, action, source order나 label을 직접 생성하지 않게 한다.

## 구성별 상태

| 구성 | 상태 | 설명 |
|---|---|---|
| SourceUnit 기반 답변 | 운영 중 | 서버가 선택 ID에서 exact 근거를 복원한다. |
| Facet-slot selection | 운영 중 | 필수 facet별 scalar enum 계약을 사용한다. 동일 ID의 여러 facet 할당은 허용한다. |
| Server-derived answerability | 운영 중 | evidence/selection/reconstruction/validator 전체 통과 후에만 true다. |
| Presentation sidecar | 운영 중 | Answer JSON을 바꾸지 않는 branch·phase·marker·style metadata다. |
| Answer style routing | 운영 중 | 검증된 statement를 질문 유형에 맞는 화면 구조로 표시한다. |
| Controlled generation | 개발 중 | Schema, prompt, mock output, fail-closed validator까지 구현했다. |
| Controlled generation Live | 보류 | 병원 데이터 외부 전송과 provider 승인 전에는 연결하지 않는다. |
| Semantic entailment | 보류 | `semantic_support_pending=true`; 재서술 의미 보존의 별도 평가가 필요하다. |
| Groq | 조건부 사용 가능 | 기존 Facet-slot selection provider. 최신 통합 작업의 실제 호출은 0회다. |
| Gemini | 미사용 | 현재 production adapter와 승인된 live 경로가 없다. |

## Presentation sidecar

Sidecar는 `statement_index`, `source_unit_id`, `branch`, `phase`, `source_order`, `leading_marker` 같은 표시 metadata만 가진다. 임상 요약문이나 새 clinical text를 저장하지 않는다.

- `Statement.text` 변경 없음
- `Evidence.quote` 변경 없음
- `chunk_id` 변경 없음
- Source order 재정렬 없음
- 의미 기반 dedup 없음
- Validator 통과 후에만 UI 전달

관련 파일: `mvp/presentation.py`, `mvp/answer_ui.py`, `mvp/app.py`

## 질문 유형별 현재 출력 구조

| 질문 유형 | 현재 표시 구조 | 임상 text 처리 |
|---|---|---|
| 사실 확인 | 짧은 직접 문단 | 검증된 exact statement |
| 절차 | 단계형 목록, branch/phase heading | 원순서와 leading marker 유지 |
| 준비 | Checklist형 목록 | 내용 변경 없음 |
| 주의사항 | Warning/monitoring bullet | 내용 변경 없음 |
| 비교 | 현재 검증 문장/근거 표시; controlled table synthesis는 보류 | 새 비교값 생성 금지 |
| 요약 | 핵심 heading + 세부 항목 | exact statement만 배치 |
| 제품별 | 제품/제제별 근거 항목 | 근거 metadata 범위 안에서 표시 |
| 시간 순서 | 전/중/후 heading | phase metadata 사용 |
| 성인/소아 | 공통/성인/소아 heading | branch별 유사 문장도 각각 유지 |

## Controlled generation 계약

Provider-neutral Mock은 다음을 준비했다.

- Request-scoped SourceUnit ID enum
- Supporting ID 명시
- Server citation 재생성
- Number, unit, time 검사
- Condition, negation 검사
- Branch, phase, action 검사
- Evidence coverage 검사
- Schema 외 ID, unsupported synthesis와 의미 변경 fail closed

실제 provider 연결 전에는 semantic entailment를 충분히 평가할 수 없으므로 production의 exact SourceUnit 계약을 대체하지 않는다.

관련 파일: `mvp/controlled_generation.py`, `tests/test_controlled_paraphrasing.py`

## Validator chain

```text
provider response schema
  → facet key/allowlist/contract 검사
  → distinct SourceUnit limit(16)
  → source order
  → AnswerCoverage(group/branch/phase/action/query action)
  → server reconstruction
  → validate_answer()
     ├─ exact citation/source sentence
     ├─ number/unit/time
     ├─ condition/negation/contraindication
     ├─ unsupported action/synthesis
     ├─ duplicate evidence
     └─ source order/evidence coverage
  → presentation sidecar
  → UI
```

어느 단계든 실패하면 answerable=false로 안전 종료하며 자동 보충·축소·재정렬·재호출로 통과시키지 않는다.

## 아직 필요한 승인과 구현

- 병원 데이터 외부 전송 정책 확인
- 사용할 generation provider와 계정의 명시적 승인
- Controlled generation Live/semantic entailment 평가
- 비교표·요약 재서술의 의미 보존 검증
- 기존 exact 답변보다 명확히 낫고 모든 validator를 통과할 때만 production 연결
