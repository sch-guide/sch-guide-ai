### MM003 해결

MM003 miss의 직접 원인은 gold가 아니라 parser였다. PDF grid는 다중 열 header를 찾았지만 본문 셀 값 대부분을 빈 값으로 추출했다. 일반 규칙으로 다중 열 표 본문 행의 75% 이상이 한 셀 이하일 때 `sparse_body`로 판정하고, 기존 substantive catalog parent group을 row evidence로 사용한다.

Table-only search에서는 정확한 숫자+단위/시간 token을 full lexical token보다 높게, Korean helper n-gram을 낮게 가중한다. Production BM25는 변경하지 않았다.

### Citation과 UI

- Citation: document, page, table ID, row index
- Exact cell/row text: local Streamlit UI 메모리에서만 표시
- Artifact: ID, bbox, fingerprint, SHA-256만 저장
- Header/cell 관계와 값은 추정하지 않음

Production repository에는 table cell/geometry schema가 없다. Local/Cloud repository migration 없이 table을 main answerability에 연결하면 backend drift가 생기므로 이번 후보에서는 evaluation-only로 유지한다.
