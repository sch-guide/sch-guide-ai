SCHAT 시스템 설계 — 멘토 검토용 Current Truth

기준일: 2026-09-19 기준 브랜치: boha-rag 목적: 현재 실행 구조를 10초 안에 파악할 수 있는 구조도와 그 근거 제공 비범위: Production 코드·검색·validator·DB/schema·Gold/UAT 변경, 외부 Provider 호출

먼저 읽을 한 문장

현재 SCHAT의 Hybrid Retrieval은 자체 BM25의 단어 기반 검색과 MiniLM의 의미 기반 vector 검색을 병렬로 수행하고, 두 순위를 RRF로 합친 뒤 규칙 기반 reranker와 Evidence 안전 경계를 통과시키는 구조다.

핵심 불변식:

  1. Vector similarity만으로 답변 가능성을 결정하지 않는다.
  2. BM25와 vector 후보는 RRF로 결합한 뒤 기존 규칙 기반 검사를 통과한다.
  3. Parent 의미 단위를 부분적으로 잘라 답변하지 않는다.
  4. 승인된 AI Provider는 임상 문장을 자유 생성하지 않고 허용된 SourceUnit ID만 선택한다.
  5. 서버가 exact text를 재구성하고 validator를 통과한 결과만 표시한다.
  6. 근거가 부족하거나 계약이 깨지면 자동 보완하지 않고 abstain한다.

한 번에 여러 요소를 바꾸지 않고 검색 방식만 교체해 성능 차이를 비교한다.

공정 비교 조건:

  • 사람이 검수한 동일 positive Gold와 동일 질문 집합
  • 동일 chunk snapshot, 문서 scope, query normalization/expansion
  • 동일 Top-k와 cutoff: 1, 3, 5, 10
  • negative/out-of-scope는 positive IR aggregate와 분리
  • heading-only chunk를 Gold로 사용하지 않음
  • retrieval 결과에서 Gold를 자동 확정하지 않음
  • embedding model과 corpus fingerprint 명시

채택은 aggregate뿐 아니라 temporal, product-specific, paraphrase, procedure, fact-specific, branch-specific, table, image, negative/out-of-scope 실패 유형과 안전/UAT 회귀를 함께 본다. 기존 Hybrid 변경은 별도 설계와 승인이 필요하다.

9. 상세 기술 설명과 변경하지 않은 범위

질문 처리

Streamlit이 질문과 명시적 문서 범위를 수집하면 plan_query()가 정규화, 오탈자 보완, intent, domain, 질문 유형, 비교 대상, branch/phase, procedure 요구를 분석한다. Clarification이 필요하거나 domain 밖 질문이면 Provider 호출 전에 차단한다.

후보 검색과 재정렬

BM25는 확장 질의를 대상으로 lexical 점수를 계산한다. Vector 경로는 동일 MiniLM 질의 vector를 사용하되 Local은 FAISS, Staff는 pgvector RPC가 dense 후보를 반환한다. RRF는 서로 다른 점수계를 rank 기반으로 결합하며 확률을 산출하지 않는다.

rerank()는 heading-only 또는 지나치게 짧은 본문, topic compatibility, lexical support, dense threshold, 핵심어 coverage, focus, 비교 질문의 entity 다양성, 중복과 seed 수를 검사한다.

Context와 Evidence

expand_context()는 같은 문서·section의 연결된 앞뒤 문맥, 페이지 거리, 절차 순서, 명시적 branch와 parent block을 보존한다. 불완전한 parent block은 answer path에서 차단한다. assess_evidence()는 LLM 호출 전과 prompt budget 적용 후 필수 document/entity/branch/phase/group/facet coverage를 검사한다.

변경하지 않은 범위

  • 이 문서 작성 당시의 공식 문서 내용
  • src/ Production 코드와 설정
  • Retrieval / validator / database schema
  • test fixture, Gold, metric 결과
  • .env 및 secret
  • 외부 Provider/API 호출 상태
  • Git branch, commit, tag, push

이 산출물은 실제 실행 코드를 설명하는 검수용 문서다. 존재하지 않는 component를 제안 구조처럼 추가하지 않으며, 평가 코드를 Production 실행선에 포함시키지 않는다.
